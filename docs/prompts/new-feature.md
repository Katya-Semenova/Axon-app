# new-feature — универсальный промт разработки фичи (Axon)

> Наш процесс разработки фичи: вбирает лучшее из плагина `/feature-dev`
> (исследование → архитектура → реализация → ревью) и продакт-дискавери
> (Cagan, JTBD, Shape Up, Torres). Работает под любым AI, без плагинов.
>
> **Пути адаптированы под Axon** (плоская структура: `docs/` в корне, без `product/`).
> Архитектура Axon: холст на Zustand-сторе (`lib/store.ts`), UI-кит в
> `app/components/ui/`, слой данных — доски как JSON-документы (см.
> `docs/decisions/ADR-003-data-layer.md`). Это НЕ FSD-шаблон курса.

Промт из двух частей:
1. **Интервью** — поймать намерение и контекст (2–6 вопросов).
2. **Реализация** — исследование → архитектура → код → ревью.

---

## Шаг 0 — Как реализуем
- Есть параллельные sub-агенты (Claude Code `Agent`/`Task`) → роли можно раздать агентам.
- Нет → выполняй роли **последовательно в одном контексте**, меняя «шляпу»:
  исследователь → архитектор → кодер → ревью логики → ревью безопасности → тех-лид.

## PRD-first: не пиши код без спецификации
Источники правды: `docs/spec.md` (логика, модель данных), `docs/screens/<url>.md`
(логика + `## Визуал` экрана), `docs/PRD.md` (продуктовый контекст).

| Что есть | Действие |
|---|---|
| Фича описана в `spec.md` / `screens/<url>.md` | Идём: интервью → бриф → реализация |
| Спека есть, но фича не описана | Сначала допиши (логику — в `spec.md`, экран — в `docs/screens/<url>.md`), потом код |
| Спеки нет | Предложи собрать минимум: что строим, для кого, зачем |

Меняешь поведение продукта — обнови `docs/spec.md` в том же коммите (железное правило AGENTS.md).

# Часть 1 — Интервью

**Спрашивай только то, что нельзя вывести самому.** Файлы, архитектуру в рамках
текущего стека, паттерны, риски, сложность — определяешь сам. Спрашивай: **что
строим, что за рамками, поведение в крайних случаях.** Аудиторию/цель бери из
`PRD.md`/`spec.md`, не переспрашивай.

**Новая технология/сервис** (новая БД, платёжка, auth, внешний API) — не выбирай
молча: предложи дефолт и **спроси**, нет ли своего требования.

**Протокол:** один вопрос за раз; предлагай 2–3 варианта; пропускай то, что уже
известно; разговорно, 2–6 вопросов. Перед интервью бегло изучи проект (точки
входа, похожие фичи, конвенции, модель данных) и прочитай spec/screens/PRD.

**Вопросы (адаптивно):** 1) намерение, 2) аудитория/успех (из PRD — не дублируй),
3) крайние случаи (пусто/ошибка/нет доступа/длинные данные), 4) исключения.

**Бриф и одобрение.** Собери короткий бриф (намерение, аудитория, критерии успеха,
исключения, контекст проекта, чеклист ревью) и покажи: «Вот план. Запускаю?»
Не начинай код без одобрения. Сохрани бриф в `docs/briefs/<feature-name>.md`.

# Часть 2 — Реализация

## Шаг 1: Сложность
| Уровень | Триггеры | Кто участвует |
|---|---|---|
| **SIMPLE** | 1–2 файла, без новых зависимостей/миграций | кодер + один общий ревьюер |
| **MEDIUM** | 3–5 файлов, новые зависимости, API/БД | кодер + ревью логики + ревью безопасности + тех-лид |
| **COMPLEX** | 6+ файлов, миграции БД, auth/платежи | то же + разбивка на части + анализ рисков до кода |

## Шаг 2: План
Разбей бриф на задачи (файлы, действия, зависимости). Для MEDIUM/COMPLEX — покажи план.

## Шаг 3: Реализация ролями
1. **Исследователь** — прочитай 5–10 ключевых файлов; выпиши паттерны.
2. **Архитектор** — 2–3 варианта (минимальный/чистый/прагматичный), выбери с обоснованием.
3. **Кодер** — реализуй по конвенциям проекта.
4. **Ревью логики** — по чеклисту брифа: критерии успеха, исключения, edge cases.
5. **Ревью безопасности** — IDOR, авторизация, секреты, инъекции, XSS; сверься с правилами проекта.
6. **Тех-лид** (MEDIUM/COMPLEX) — не противоречит ли прошлым ADR, нет ли дублирования.

Критичные замечания (🔴) применяй сразу, остальные предложи пользователю.

## Шаг 4: Верификация
Перед «готово»: запусти сборку/тесты/dev; проверь работу; для веб — пройди путь
пользователя в браузере (Playwright); тесты должны проходить.

## Шаг 5: Итог
Короткий итог (статус, сложность, выполнено, файлы, ревью логика/безопасность/архитектура,
нерешённые вопросы). После — обнови `docs/spec.md` и память проекта.
