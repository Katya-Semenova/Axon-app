## 🚑 Если Mac начал тормозить / вентилятор шумит

**1. Убить все dev-серверы Next** (самая частая причина тормозов — накопившиеся серверы).
Безопасно: VS Code и чаты Claude не пострадают.
```
pkill -f "next dev"
```
Что увидишь: ничего (тишина = сработало). Если напишет «no matching processes» — серверов и не было.

**2. Посмотреть, какие процессы node живут** (диагностика: кто ест память).
```
ps aux | grep "[n]ode"
```
Что увидишь: список строк — по одной на процесс. Много строк со словом `next` = серверы плодятся.

**3. Тяжёлая артиллерия — перезагрузка Mac.** Гарантированно чистит всех «сирот».
Меню  → «Перезагрузить». Перед большим рабочим днём — полезно в любом случае.

## 📦 Git — посмотреть состояние (ничего не ломает, можно смело)

**Что сейчас изменено и не закоммичено** (запускать перед началом работы в любом чате):
```
git status
```
Что увидишь: «nothing to commit» = чисто, можно работать. Список файлов = кто-то (ты или чат) не закоммитил.

**Последние коммиты — что происходило в проекте:**
```
git log --oneline -10
```
Что увидишь: 10 строк, каждая = один коммит (номер + описание). Самый свежий сверху.

**На какой я ветке:**
```
git branch --show-current
```
Что увидишь: имя ветки, например `feature/highcharts-spike`.

## ⬆️ Git — отправить работу на GitHub (push)

Пуш = отправить локальные коммиты на GitHub (резервная копия + доступ для деплоя).
Пуш у нас **не** запускает деплой — это безопасно. Деплой всегда отдельно, руками.

**Запушить текущую ветку (первый раз для новой ветки):**
```
git push -u origin feature/highcharts-spike
```
Что увидишь: несколько строк прогресса и в конце `branch ... set up to track`. Дальше для этой ветки хватит просто `git push`.

## ⚠️ Чего руками лучше НЕ делать
- `killall node` — убьёт заодно служебные процессы чатов Claude (MCP-серверы). Используй `pkill -f "next dev"`.
- `git push --force`, `git reset --hard` — переписывают историю/стирают правки; только по явному плану.
- Любые `rm -rf` — безвозвратное удаление; не запускать по советам из интернета.
- На проде: никаких сбросов базы (`prisma migrate reset`) — там реальные данные (правило Урока 7, Задание 6).
