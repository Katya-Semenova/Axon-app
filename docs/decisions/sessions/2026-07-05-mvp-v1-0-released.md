## Принятые решения

- IDOR тестируем интеграционно (Vitest), не e2e: у доски нет URL — браузером чужую доску
  не запросить; зовём те же серверные функции, что зовёт клиент.
- 429 проверяем на ведре `request-password-reset`, не `sign-in` — иначе лочим параллельные
  логин-тесты; ловим «429 встретился в серии», а не «ровно на 4-м» (ведро в памяти сервера).
- e2e — локаль `ru-RU` в конфиге Playwright: язык резолвится по Accept-Language (fallback en),
  без этого воркспейс в тестах английский.
- Шесть скиллов силы — вариант B (в репо, `.claude/skills/`), см. ADR-013.

## Находки

- **Гонка «гостевой ветки»:** сразу после регистрации `useSession` на клиенте ещё null —
  загрузка файла в этот момент идёт по гостевому пути (проект НЕ создаётся). В тестах ждём
  кнопку «Выйти». Для живого пользователя окно ~секунда; поправить UI — по желанию (backlog?).
- **Шаринг раньше первого автосейва:** демо-сид нового проекта доезжает в БД асинхронно
  (BoardSync); публичная страница серверная — если получатель открыл ссылку до первого
  сохранения, увидит «недоступна» до перезагрузки. В реальной жизни окно крошечное.
- **Модальный «Обучающий тур»** перехватывает клики первого входа в воркспейс — e2e закрывает
  его хелпером `dismissTourIfShown`.
- В `.env.test` обязателен «test» в `DATABASE_URL` — idor.test.ts иначе останавливается
  (защита боевой базы, правило №4 AGENTS.md).
