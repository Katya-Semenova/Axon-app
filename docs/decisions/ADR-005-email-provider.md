# ADR-005 — Провайдер писем аккаунта: Resend + React Email

- **Статус:** ✅ Принято
- **Дата:** 2026-06-16
- **Контекст:** Урок 4, Шаг 6 (письма аккаунта). Связано с [ADR-004](ADR-004-auth-library.md) (Better Auth).

## Контекст
После подключения auth (Шаг 5) нужны письма аккаунта: прежде всего **сброс пароля**
(«забыл пароль» без письма не закрыть), плюс уведомление **«пароль изменён»** и
**welcome** при регистрации. Нужен сервис отправки + способ верстать письма.

## Решение
- **Resend** ([resend.com](https://resend.com)) как сервис отправки. Бесплатный тариф
  (100 писем/день, 3000/мес) с запасом покрывает редкие письма аккаунта.
- **React Email** (`react-email` + `@react-email/components` + `@react-email/render`)
  для вёрстки писем как TSX-компонентов; превью — `npm run email:dev`.
- **Домен подтверждён в Resend** (DKIM/SPF/MX-записи добавлены в DNS Timeweb,
  верификация пройдена 2026-06-16). Отправитель — `Axon <noreply@axon-app.ru>`.
- **Подключение к auth** через колбэки Better Auth: `sendResetPassword`,
  `onPasswordReset` и `databaseHooks.user.create.after` (welcome) в `lib/auth.ts`;
  функции отправки — `lib/email.ts`; шаблоны — `emails/`.
- **Двуязычность (RU/EN)** по локали пользователя: локаль определяется из заголовков
  запроса (cookie выбора → Accept-Language → fallback), хелпер `resolveLocaleFromHeaders`
  в `i18n/request.ts`. Строки писем — внутри шаблонов (письма рендерятся вне
  next-intl-контекста).
- **Секрет** `RESEND_API_KEY` — только в env (локально опционально, на сервере
  `.env.production` обязательно), вне git, резерв в Bitwarden. Без ключа отправка
  тихо пропускается с логом (локальная разработка не падает).

## Почему так (а не иначе)
- **Resend, а не SMTP/Sendgrid:** простой API, бесплатный тариф, React Email «из
  коробки», работает из РФ-инфраструктуры (исходящий HTTPS на api.resend.com).
- **React Email, а не голый HTML:** письма верстаются как компоненты, единый Layout
  и бренд, живое превью.
- **Колбэки Better Auth, а не свой flow:** токены сброса, срок жизни (1ч) и эндпоинты
  (`/request-password-reset`, `/reset-password`) уже реализованы библиотекой.

## Последствия
- Письма верстаются inline-стилями (требование почтовых клиентов) — осознанное
  исключение из правила «без хардкода хексов» (токенов Tailwind в почте нет).
- Реальная отправка проверяется **на проде** (ключ только на сервере); локально —
  превью шаблонов.
- **Отложено:** подтверждение email (verify-email) — после Урока 5 (переключатель
  `requireEmailVerification` + один шаблон). Rate-limit на `/api/auth/*` против
  email-бомбинга — Шаг 9 (пока дефолтный лимит Better Auth).
