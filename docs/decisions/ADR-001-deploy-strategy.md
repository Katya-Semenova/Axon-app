## Date
2026-06-14

## Context

Нужен понятный, повторяемый и безопасный способ выкладывать Axon в публичный доступ.

Факторы, определяющие выбор:
- **Пользователь — дизайнер, не разработчик.** Стратегия должна быть прозрачной и не требовать ручного администрирования сервера.
- **Axon — чистый фронтенд-прототип.** Нет бэкенда, БД, авторизации, API-роутов и серверных задач; «AI-инсайты» работают на `lib/mockData.ts` (демо-данные на клиенте). **Секретов/переменных окружения нет** (см. `docs/architecture.md`, раздел «Секреты»). Это самый простой класс деплоя.
- **Стек:** Next.js 15 (App Router), статически/SSR-сборка без серверного состояния.
- **Регион:** пользователь в России за VPN. Это влияет на выбор хостинга (доступность, оплата зарубежных сервисов).
- **Текущее состояние:** проект **уже** задеплоен на Vercel (`https://axon-app-chi.vercel.app/`), репозиторий на GitHub (`git@github.com:Katya-Semenova/Axon-app.git`), авто-деплой по push в `main` уже настроен и работает.

## Decision

**Остаёмся на Vercel.** Хостинг-платформа с авто-сборкой и авто-деплоем:

- Push в ветку `main` → Vercel автоматически собирает (`next build`) и выкатывает новую версию.
- HTTPS, CDN, оптимизация изображений (`next/image`) — из коробки, настраивать вручную не нужно.
- Версия прода = последний коммит в `main`. Откат = выбрать предыдущий деплой в дашборде Vercel (или `git revert` + push).
- VPS, Docker, nginx, Certbot из рецептов урока (05/07/08/14) **не используем** — Vercel закрывает всё это сам.

**Режим выката — авто по push, с дисциплиной:**
поскольку случайный push в `main` сразу уходит в прод, push в этом проекте — **осознанный отдельный шаг**: сборка проверяется локально + проходит security-проверка ДО push.

## Alternatives Considered

### Свой VPS (ручной SSH / git-based / Docker) — рекомендуемый базовый маршрут урока
**Хорошо:** полный контроль, обучает DevOps, нет вендор-лока.
**Почему НЕТ для Axon:** требует администрирования сервера (обновления, nginx, HTTPS, фаервол) — лишняя нагрузка для дизайнера ради фронтенда без бэкенда. Плюс **оплата зарубежного VPS из РФ затруднена**, а сборка `next build` на слабом боксе (≤1 ГБ) выедает память. Ценности под текущий проект не добавляет.

### CI/CD (GitHub Actions)
**Хорошо:** прогон тестов/линта перед выкатом, стандарт для команды.
**Почему пока НЕТ:** избыточно для соло-прототипа без тестов. Vercel и так делает сборку при push. **Можно добавить позже**, когда появятся тесты или команда.

### Netlify / Render / Railway
**Хорошо:** аналогичные Vercel платформы.
**Почему НЕТ:** Vercel уже подключён и работает; это «родная» платформа для Next.js. Менять рабочее без причины — лишний риск.

### scp / rsync (копирование артефактов)
**Почему НЕТ:** нет нормальной истории и отката, легко получить «на сервере не то, что в репо».

## Risks & Conditions to Migrate (когда пересмотреть это решение)

- ⚠️ **Доступность из России.** Сайт на `*.vercel.app` обслуживается инфраструктурой Vercel; нужно следить, доступен ли он целевой аудитории из РФ без VPN (та же проблема фильтрации, что у дипломного проекта). **Условие переезда:** если Vercel станет недоступен для конечных пользователей из целевого региона — рассмотреть хостинг с российским/доступным IP.
- ⚠️ **Появится реальный бэкенд.** Если заменим `mockData` на живой AI (напр. GigaChat) + БД + auth — появятся секреты и серверная нагрузка. Тогда: переменные → Vercel → Settings → Environment Variables **и** бэкап в Bitwarden (НЕ iCloud, НЕ git); при тяжёлой серверной логике/файлах — пересмотреть в пользу VPS/платформы с бэкендом.
- ⚠️ **Оплата.** Сейчас хватает бесплатного тарифа Vercel. Если упрёмся в лимиты и понадобится Pro — оплата из РФ может быть проблемой; заранее заложить обходной путь или альтернативу.
- ⚠️ **Кастомный домен.** При переходе на свой домен (вместо `axon-app-chi.vercel.app`) — настроить DNS в Vercel; зафиксировать отдельно.

## Consequences

- Все будущие команды «задеплой» = «закоммить → проверить → push в `main`» (Vercel выкатит сам). «Откати» = revert коммита + push, либо откат деплоя в дашборде Vercel.
- Перед каждым push в `main`: проверка локальной сборки + `/security-check` как ворота.
- После настройки/изменений инфраструктуры — отразить в снимке инфраструктуры (Шаг 6 урока).
- Если стратегия изменится (переезд с Vercel, добавление CI/CD или бэкенда) — создать новый ADR или обновить этот с причиной и датой.
