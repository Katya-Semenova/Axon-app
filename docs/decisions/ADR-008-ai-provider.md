# ADR-008: ИИ в продукте — провайдер-агностичный слой (дефолт OpenRouter, GigaChat — опция)

| | |
|---|---|
| Статус | ✅ Принято |
| Дата | 2026-06-17 |
| Контекст | Урок 5, Шаг 1 — сделать ИИ настоящим ядром продукта |

## Контекст
ИИ — ядро ценности Axon («загрузил файл → ИИ достаёт инсайты»). До сих пор инсайты
строит движок **по правилам** (`lib/insight-engine`), а граница `ParsedTable → BoardData`
заложена как «сменный разъём» под будущий ИИ. Урок 5 ставит в этот разъём настоящий ИИ.

Нужен выбор провайдера. Два полюса:
- **Claude / OpenAI** — лучшее качество и «импрессия» на демо, но для РФ-аудитории
  напрямую недоступны: геоблок + нельзя оплатить.
- **GigaChat (Сбер)** — официальный API, оплата в рублях, работает в РФ; для прод-аудитории
  из России — единственный реально оплачиваемый вариант. На демо выглядит скромнее.

Владелец колеблется: на этапе показа MVP важнее «показать хорошо», окончательный выбор
провайдера — позже.

## Решение
**Не выбираем провайдера намертво — строим провайдер-агностичный слой `lib/ai/`.**
- Код продукта общается с единым интерфейсом `LLMClient`; конкретный провайдер — **адаптер**.
- Смена провайдера = смена конфига/адаптера (env), **не переписывание**.
- **Дефолт для MVP-демо — OpenRouter** (один ключ → актуальные модели Claude/GPT; дефолт-модель
  конфигом, напр. `claude-sonnet-4-6`).
- **GigaChat — поддерживаемая опция** (адаптер-заготовка) для прод-аудитории РФ.
- **Финальный выбор OpenRouter ↔ GigaChat отложен осознанно** — агностичность это позволяет.
- Ключи провайдеров — **только сервер** (`.env*`, не в git); ИИ-вызовы идут из серверного
  route `/api/ai/*`, не из браузера.

## Первое применение — извлечение инсайтов (гибрид)
ИИ встаёт в разъём `ParsedTable → BoardData`:
- **ИИ решает** (интеллектуальная часть): состав дата-сетов, тип графика (из 10), заголовок,
  **нарратив-инсайт словами** (plain English; протекает в слайд).
- **Код считает** фактические числа строк из реальных данных по «рецепту» ИИ — **защита от
  галлюцинации цифр** (критично для дата-продукта).

## Приватность
- Провайдеру (OpenRouter → US-LLM) уходит **только схема колонок + выборка строк**, не весь файл.
  Полная таблица и точные суммы остаются в браузере/у нас.
- Это смягчает (не отменяет) уход данных третьей стороне — учтено в выборе «схема+выборка».
- Для РФ-аудитории на проде уход данных в США может быть неприемлем → ещё один довод за
  GigaChat-опцию. Агностичный слой даёт переключиться без переделки.

## Границы доступа и расход
- ИИ-разбор — **только вошедшим** (контроль расхода/абьюза, лимит токенов на пользователя).
- Гость получает разбор **по правилам** (текущее поведение), без ИИ.
- Rate-limit на `/api/ai/*`.

## Надёжность
- Правила (`lib/insight-engine`) **остаются как fallback**: нет ключа / таймаут / ошибка API /
  невалидный ответ ИИ → тихо считаем по правилам. ИИ сломался — продукт жив.

## Альтернативы
- **Прибить к одному провайдеру** (только GigaChat, как было в spec) — меньше кода сейчас,
  но смена = переписывание; и блокирует «показать хорошо на демо». Отклонено.
- **Только Claude/OpenAI напрямую** — лучшая импрессия, но недоступно/неоплачиваемо в РФ
  для прод-аудитории. Отклонено как единственный путь (оставлено через OpenRouter для демо).
- **Полный ИИ (и числа от ИИ)** — проще промпт, но галлюцинация цифр ломает доверие. Отклонено
  в пользу гибрида.
- **Async-очередь + центр уведомлений** — мощнее, но это отдельная фича (бэклог). Для MVP —
  синхронно (спиннер, EC-3 = loading).

## Последствия / долг
- Лимит токенов на пользователя — для MVP простой кап на запрос; точная квота/учёт — позже.
- UI-дисклоуз «данные уходят провайдеру» — в бэклог (для MVP зафиксировано здесь).
- GigaChat-адаптер — заготовка; полная проверка боем при включении на проде.
- Промт урока `prompts/01-ai-openrouter.md` адаптирован под наш агностичный слой.
