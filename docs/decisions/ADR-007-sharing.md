# ADR-007: Публичная ссылка на презентацию (share-link)

| | |
|---|---|
| Статус | ✅ Принято |
| Дата | 2026-06-17 |
| Контекст | Шаг 12 — «зафиналить деку в виде ссылки» |

## Контекст
Пользователю нужно отдать готовую деку «как ссылку»: получатель открывает её **без
входа**, read-only. Прежний режим «Показ» был макетом (фейковая ссылка
`axon.app/s/…`, кнопка «Скачать» с пустым обработчиком). Экспорт в PPTX/PDF —
другой механизм (генерация файла), отложен в бэклог.

## Решение
Ссылка-токен на доску, хранится в БД:
- Модель `ShareLink { id, token (unique, cuid), boardId → Board, createdAt, revoked }`.
- Создание / отзыв / чтение активного токена — **только владелец** (ownerId из
  серверной сессии, IDOR-защита, как в `app/actions/board.ts`). Гость → вход +
  сохранение доски (`AuthModal` + `createProjectFromData`, Шаг 7b), затем ссылка.
- Публичный роут `/p/[token]` (без входа) грузит деку через `getSharedBoard(token)`
  и рендерит слайды read-only тем же `SlideArchetypeRenderer`, что и редактор.
- **Отзыв** (`revoked = true`) → «Презентация недоступна».
- Срок жизни — **бессрочно до отзыва** (см. `screens/public-presentation.md`).

## Приватность
`getSharedBoard` отдаёт **урезанную деку** — только слайды + дата-сеты, на которые
они ссылаются, + тему. Без инсайтов, связей, позиций и чужих досок.

## Альтернативы
- Кодировать деку прямо в URL/JWT — не нужен бэкенд, но ссылки огромные, нет отзыва,
  данные «навсегда» у получателя. Отклонено.
- Сразу экспорт файла (PPTX/PDF) — более тяжёлый отдельный механизм; в бэклоге.

## Последствия / долг
- Токен — `cuid` (непредсказуемый, ~25 символов), но не крипто-случайный. При росте
  чувствительности — заменить на крипто-токен подлиннее.
- Бесплатный Neon засыпает: первое создание ссылки после простоя может отвалиться по
  таймауту (повтор помогает); на проде (Selectel) — не проблема.
- «Сделать копию себе» получателем и протухание ссылки — на будущее.
