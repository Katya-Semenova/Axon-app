# ADR-009: Монорепо — сервис и лендинг как раздельные приложения с общим пакетом UI

| | |
|---|---|
| Статус | ✅ Принято (Шаг 0); деплой-часть — в работе (Шаг 1) |
| Дата | 2026-06-20 |
| Контекст | Урок 6, Шаг 0 — публичная упаковка: лендинг + SEO + PWA |

## Контекст
До Урока 6 продукт был **одним** Next.js-приложением в корне репозитория. На Уроке 6
появляется **публичный лендинг** — второй деплой-артефакт, который меняют часто. Держать его
в одном приложении с сервисом невыгодно: любая правка лендинга запускала бы полную пересборку
и рестарт всего сервиса (медленно, общий build-гейт, риск задеть активных пользователей).

Дополнительный факт нашего проекта: **лендинг уже существовал** отдельным проектом в соседней
папке `../axon-landing` (Next 16, со своими анимациями framer-motion/gsap/lenis/lottie) — его
надо было втянуть в общую структуру, а не собирать с нуля.

## Решение
Перевели продукт на **монорепо** (npm workspaces). Весь код уехал в `development/`, корень
репозитория стал чистым (`docs/` + `development/` + правила-хабы).

```
axon-app/
├── docs/  CLAUDE.md  AGENTS.md  .claude/
└── development/
    ├── package.json                ← workspace: apps/*, packages/*
    ├── packages/ui/  (@axon/ui)    ← токены бренда (цвета+радиусы), единый источник
    └── apps/
        ├── app/      (Next 15.5)   ← сервис
        └── landing/  (Next 16)     ← лендинг (перенесён из ../axon-landing)
```

- **`@axon/ui`** — единый источник бренда (DESIGN.md): `src/styles/theme.css` с цветами и
  радиусами. Импортят обе apps → ноль дублирования, один бренд.
- **Раздельные сборки:** `npm run build -w apps/app` и `-w axon-landing` собираются независимо.
- **Перенос — через `git mv`** (история сервиса сохранена). Точка отката — коммит `961cbec`.
- **Разные мажоры Next** (15 у сервиса, 16 у лендинга) уживаются в одном workspace (React 19 у
  обоих); выравнивание версий — отдельная задача при необходимости, не блокер.

## Что НЕ вынесли (осознанно, прагматично)
- **React-компоненты UI-кита остаются в `apps/app`.** Они связаны с доменом (`@/lib/store`,
  `@/lib/types`, `@/i18n`), и вынос в пакет создал бы циклы. В `@axon/ui` пока **только токены** —
  этого достаточно для единого бренда. Промотим компоненты позже по необходимости.
- **Палитра лендинга временно своя.** Лендинг импортит `@axon/ui` (связь есть), но его оттенки
  (cream `#F4F0E8`, navy `#1A2742`, gold `#C8A86B`) чуть отличаются от сервиса. Сведение к одному
  источнику — при редизайне лендинга (Шаг 1).

## Деплой — отложен до Шага 1 (важно)
По уроку (`prompts/00-monorepo-split.md`, п.8) сервис надо сделать самостоятельным деплой-юнитом
на новом пути уже в Шаге 0. **Мы отступили от этого осознанно:**
- Деплой-рецепт (`Dockerfile`/`docker-compose.yml`/`deploy.sh`/`scripts/deploy-remote.sh`)
  **нельзя проверить в текущем окружении** (нет локального Docker, нет доступа к VPS).
- Монорепо + `output: standalone` имеет известный нюанс (нужен `outputFileTracingRoot`,
  меняется структура standalone) — высокий риск ошибиться вслепую и сломать прод.
- Поэтому правку рецепта переносим в **Шаг 1**, где публикуем по-настоящему и проверяем вживую
  (там же лендинг становится отдельным деплой-юнитом и проверяется независимость).
- **Защита на время отсрочки:** в начало `deploy.sh` и `deploy-remote.sh` добавлен стоп-кран
  (`exit 1` с сообщением) — случайная публикация со старым рецептом остановится, а не сломает
  прод молча.

## Последствия / долг
- Починить деплой-рецепт под монорепо в Шаге 1 (build из workspace; `outputFileTracingRoot`;
  новые пути; сервис и лендинг — раздельные деплой-юниты) и снять стоп-кран.
- Свести палитру лендинга к `@axon/ui` (редизайн, Шаг 1).
- Возможно выровнять Next 16 ↔ 15 (если всплывут конфликты).
- История проекта `axon-landing` осталась в исходном репо `../axon-landing` (не перенесена).

## Альтернативы
- **Оставить одно приложение** — проще, но лендинг рестартил бы прод сервиса при каждой правке.
  Отклонено (ради независимого деплоя — суть Урока 6).
- **Вынести весь UI-кит в `@axon/ui` сразу** — больше работы и риск циклов; для каркаса лендинга
  избыточно. Отклонено в пользу «только токены».
- **Чинить деплой вслепую в Шаге 0** (по букве урока) — риск сломать живой прод без проверки.
  Отклонено в пользу починки вживую в Шаге 1.
