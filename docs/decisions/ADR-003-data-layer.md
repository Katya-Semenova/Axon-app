# ADR-003: Слой данных Axon — свой PostgreSQL на VPS, Prisma, доски как документы

> Это РЕШЕНИЕ (что и почему) для Урока 4. Пошаговое исполнение — отдельными
> подтверждаемыми заходами. Выбор auth-библиотеки — отдельным [ADR-004](ADR-004-auth-library.md)
> на Шаге 5 (там же security-обоснование).

## Status
**Принято (2026-06-16).** Исполнение — по шагам Урока 4. До этого момента у Axon
бэкенда нет: состояние холста живёт только в памяти вкладки (`lib/store.ts`,
Zustand) и при перезагрузке сбрасывается на демо-сид (`lib/mockData.ts`).

## Date
2026-06-16

## Context
- **Урок 4 — первый настоящий бэкенд.** Появляются реальные пользователи и их
  данные → нужна настоящая БД (файла/таблицы недостаточно: одновременный доступ,
  целостность, изоляция по владельцу, 152-ФЗ).
- **Аудитория — РФ** (см. [ADR-002](ADR-002-hosting-migration.md)), 152-ФЗ. VPS
  Selectel уже работает (Docker + nginx, `axon-app.ru`).
- **Решено в интервью 2026-06-16:** вход по email+паролю; в БД хранятся
  пользователи **и** их доски; библиотека входа — Better Auth (фиксируется в
  ADR-004 на Шаге 5); **много досок** на пользователя («Мои проекты»);
  AI/OpenRouter — это **Урок 5**, не сюда.
- **Axon ≠ «эталонный продукт» курса.** Курс написан под FSD
  (`entities/<entity>/api/mock-*.ts`, своя таблица на сущность). У Axon одна
  модель-граф: Insight → DataSet → Slide + Connection + позиции на холсте — всё
  всегда читается/пишется как один холст. Буквальную нормализацию «таблица на
  сущность» не делаем — она избыточна.

## Decision
1. **База — свой PostgreSQL** соседним сервисом в том же `docker-compose` на VPS
   Selectel (не Supabase). Данные под контролем, в РФ (152-ФЗ), дёшево, совпадает
   с дефолтом курса. Порт закрыт наружу — доступен только приложению. Ежедневный
   бэкап (cron).
2. **ORM — Prisma** (дефолт курса; схема в одном файле, удобно для AI).
3. **Доску храним как документ, а не нормализуем.** Таблица
   `Board { id, userId, title, data (JSON), createdAt, updatedAt }`, где `data` —
   сериализованный снимок холста (тот же `WorkspaceSnapshot` + позиции, что уже в
   сторе). Плюс таблицы пользователей/сессий Better Auth (`User`, `Session`,
   `Account`, `Verification`). Причина: холст — связный граф, который всегда
   читается/пишется целиком; дробить его на 4 реляционные таблицы — много работы
   без пользы. JSON-документ ложится на нынешний стор 1:1 → перенос минимальный и
   обратимый.
4. **Много досок на пользователя:** экран «Мои проекты» (список `Board`),
   создание/открытие/переименование/удаление. **Изоляция данных — по
   `Board.userId`** (чужая доска → 404), а не пер-сущность: под нашу модель это и
   есть правильный уровень.
5. **Auth-библиотека — Better Auth**, но оформляется отдельным решением
   **ADR-004** (Шаг 5) с обоснованием и security-частью.

## Что это меняет в исполнении Урока 4 (адаптация под Axon)
- **Шаг 3 (схема):** вместо «нормализуй все сущности» → `User/Session/Account`
  (Better Auth) + `Board(JSON)`. Сид: демо-холст из `mockData.ts` становится
  дефолтным содержимым новой доски.
- **Шаг 4 (моки → БД):** вместо «перепиши `entities/*/api`» → тонкий слой
  save/load доски (server actions / API). Стор грузит доску из БД и сохраняет
  изменения.
- **Шаг 7 (изоляция):** по `Board.userId`, не пер-сущность.
- **Шаг 8 (файлы / хранилище) — НЕ пропускаем, это ядро продукта.** Загрузка
  файла на главной (dropzone) — точка входа во весь Axon. Сейчас dropzone в коде
  **визуальная заглушка** (`app/components/landing/LandingPage.tsx`: дроп файла
  просто открывает воркспейс, файл не читается). В Уроке 4: (а) делаем загрузку
  реальной — приём файла + разбор **CSV/Excel** в строки/колонки → создаётся
  доска; (б) **храним сами файлы** (CSV/Excel, PDF, картинки, скриншоты) в
  объектном хранилище — выбор MinIO на VPS vs managed S3 в РФ делаем на этом шаге
  (отдельным решением). Полный AI-разбор PDF/картинок/SQL и извлечение инсайтов —
  это **Урок 5** (до него — упрощённые инсайты + бейдж Beta, как в spec.md EC-1).
- **Шаг 6 (письма):** подтверждение email / сброс пароля — **опционально**, можно
  отложить; решим на Шаге 5/6.

> **Примечание (не для этого ADR, для Урока 5):** AI-извлечение инсайтов и чат в
> `spec.md` завязаны на **GigaChat (Сбер)** — официальный API, оплата в рублях,
> работает в РФ, — а не на OpenRouter из учебника. Развилку OpenRouter vs GigaChat
> решим в Уроке 5 отдельным ADR. Здесь фиксируем только слой данных.

> **Гость vs аккаунт (из spec.md):** гость может загрузить файл и поработать
> *без* регистрации; вход нужен, чтобы **сохранить доску, вернуться к ней, шарить
> и экспортировать**. Значит auth — не глухая стена на всё приложение, а ворота на
> сохранение/шаринг/экспорт. Учитываем на Шагах 5 и 7.

## Alternatives Considered
- **Supabase (managed):** быстрее старт, но данные вне РФ, привязка к платформе,
  дороже на росте; у нас уже есть VPS. Отклонено (как и для БД в ADR-002).
- **Нормализованная схема** (таблицы insights/datasets/slides/connections с
  `userId`): «по учебнику», но огромный объём маппинга нынешнего стора и нулевая
  выгода (холст всегда грузится целиком). Вернуться можно, если позже понадобится
  запрашивать/шарить отдельные сущности. Отложено.
- **localStorage браузера:** не выполняет цель урока — нет общего сервера, нет
  «у каждого свой аккаунт», данные теряются при смене устройства. Отклонено.

## Consequences
- Перенос стора минимален: сериализуем существующий `WorkspaceSnapshot` в
  `Board.data`.
- Появляются **первые секреты** (пароль БД, секрет Better Auth) → заводим
  `.env.production` на сервере (права 600, вне git) + `.env.example` в репо; копия
  в **Bitwarden** (не iCloud, не git). Это отдельный подтверждаемый шаг.
- Новые экраны (вход / регистрация / «Мои проекты») — по правилу AGENTS.md
  `DESIGN.md → app/components/ui/ → экран`; строим под дизайн-систему Axon.
- `spec.md` обновляется при изменении поведения (модель данных, авторизация,
  роли/доступ) — по железному правилу AGENTS.md.
- Если позже понадобится шаринг / совместное редактирование отдельных слайдов —
  пересмотреть п.3 (возможна частичная нормализация).
