# ADR-006 — Хранилище файлов: Selectel Object Storage (S3-совместимое)

- **Статус:** ✅ Принято
- **Дата:** 2026-06-16
- **Контекст:** Урок 4, Шаг 8 (хранилище и загрузка файлов). Первая фича — аватар пользователя.

## Контекст
Нужно хранить загружаемые пользователем файлы (для начала — аватар). Файлы тяжёлые,
в реляционной БД им не место: в базе храним только **ссылку**, сам файл — в объектном
хранилище. Наш сервер — маленький VPS (1 ГБ RAM, 15 ГБ диск, Selectel).

## Решение
- **Selectel Object Storage** (S3-совместимое) как хранилище.
  - Тот же провайдер, что и VPS; данные в РФ (152-ФЗ); не нагружает наш маленький бокс.
  - Подключение через `@aws-sdk/client-s3` (стандартный S3 API).
- **MinIO на VPS — отклонён:** ещё один контейнер на 1 ГБ-боксе рискует OOM; managed S3
  снимает нагрузку и почти ничего не стоит на нашем объёме.
- **Зарубежные (AWS S3 / Cloudflare R2) — нет:** в РФ часто недоступны/нестабильны.
- **Параметры — из env** (`S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`,
  `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`, `S3_PUBLIC_URL`); ключи — секреты, только в
  `.env.production` на сервере (вне git, резерв в Bitwarden). Код — `lib/storage.ts`.

## Как устроено (Шаг 8, аватар)
- Загрузка — через свой route `app/api/avatar` (POST, multipart): проверяет сессию
  (только свой аватар, id из сессии), валидирует файл **по содержимому** (magic bytes:
  PNG/JPEG/WEBP), лимит 2 МБ; кладёт в бакет ключом `avatars/<userId>-<ts>.<ext>`;
  возвращает публичную ссылку. Запись в `User.image` — на клиенте через
  `authClient.updateUser` (обновляется и сессия). Поле `User.image` уже было в схеме —
  **миграция не нужна.**
- **Отдача аватаров — через наше приложение** (route `app/api/files/<key>`): сервер
  достаёт объект из S3 подписанным запросом и отдаёт браузеру с кэш-заголовками.
  Не зависим от «публичных доменов» провайдера (у Selectel прямой S3-URL требует
  подписи → 403), бакет может быть приватным. Открыт только префикс `avatars/`.
  _(Поправка по ходу Шага 8: сначала пробовали публичный URL Selectel — он отдавал
  403, т.к. публичное чтение у Selectel идёт через отдельный домен; перешли на отдачу
  через свой route — надёжнее и провайдеро-независимо. `S3_PUBLIC_URL` больше не нужен.)_

## Последствия
- Картинки идут через наш домен (`/api/files/...`) с кэшированием (immutable). Нагрузка
  на VPS — мизерная (аватары мелкие, кэшируются браузером).
- Для **секретных** файлов (исходные данные пользователя) позже — отдельный route с
  проверкой владельца (чужой файл → 403); `lib/storage.ts` переиспользуется.
- Реальная загрузка проверяется **на проде** (ключи только на сервере); локально без
  ключей загрузка вернёт понятную ошибку, сборка/типы не страдают.
- Антиспам загрузок (rate-limit) — Шаг 9.
