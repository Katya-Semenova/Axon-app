# ADR-010: URL приложения — подстраница `/app` (не поддомен)

| | |
|---|---|
| Статус | ✅ Принято |
| Дата | 2026-06-21 |
| Контекст | Урок 6, Шаг 1, Задание 1.1 — где живёт сервис относительно лендинга |

## Контекст
Лендинг занимает корень `/` основного домена **axon-app.ru**. Нужно зафиксировать, где
живёт сам **сервис**: на подстранице `/app` того же домена или на поддомене
`app.axon-app.ru`. От этого решения зависят индексация (Задание 3), редиректы лендинг ↔
приложение и `start_url` манифеста PWA (Задание 4) — отложить нельзя, иначе потом
переписывать манифест и роутинг.

Дополнительный фактор нашего проекта — **двуязычие**. Сервис уже двуязычный (`next-intl`,
ru/en): локаль хранится в cookie, по умолчанию определяется по языку браузера
(`Accept-Language`), не по стране/IP. Лендинг пока одноязычный (английский); двуязычный
лендинг — отдельная отложенная задача (см. `docs/backlog.md`). При этом и cookie входа
(Better Auth), и cookie языка должны переноситься между лендингом и приложением.

## Решение
**Сервис живёт на подстранице `/app`** того же домена. Поддомен не вводим.

### Почему
- **Соло-проект.** Нет команды/инфраструктуры, ради которой стоит разносить «маркетинг ↔
  продукт». Урок прямо советует: «нет явной причины разносить — оставайся на подстранице».
- **Один origin → cookie работают сами.** И cookie входа, и cookie языка делятся между `/`
  и `/app` автоматически. Поддомен потребовал бы привязывать обе cookie к родительскому
  домену `.axon-app.ru` — лишний риск (легко получить «вошёл на лендинге, а в приложении
  снова гость» или «язык не перенёсся»).
- **Меньше движущихся частей.** Поддомен добавил бы запись DNS у регистратора, отдельный
  server-блок nginx и отдельный сертификат HTTPS — без выгоды на текущем масштабе.
- **Откат дёшев.** Вынести продукт на `app.axon-app.ru` можно позже, при росте, не ломая
  ничего сделанного.

### Следствия (на что опираются дальнейшие задания)
- **nginx:** `/` → лендинг (`apps/landing`), `/app` и внутренние маршруты сервиса
  (`/login`, `/signup`, `/settings`, `/admin`, `/api`) → сервис (`apps/app`).
- **PWA (Задание 4):** `start_url: "/app"`, `scope: "/"`.
- **Редиректы:** залогиненного пользователя с `/` уводим в `/app`; гостя, открывшего
  `/app`, guard из Урока 4 отправляет на `/login`. Запуск установленного PWA
  (`display-mode: standalone`) тоже ведёт в `/app`.
- **Двуязычие:** при одном origin locale-cookie общий с сервисом — будущий двуязычный
  лендинг проще, чем при поддомене.

## Альтернатива (отклонена сейчас)
**Поддомен `app.axon-app.ru`.** Чище разделение «маркетинг ↔ продукт», независимый
деплой/масштаб, свой стек/команда. Цена: DNS + отдельный nginx-блок с HTTPS + общие cookie
сессии и языка на `.axon-app.ru`. Берём при росте проекта, не сейчас.
