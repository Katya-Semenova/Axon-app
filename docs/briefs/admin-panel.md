# Бриф — Админка (owner-панель) v1 · read-only

> Урок 5, Шаг 2. Процесс `/new-feature`. Спроектировано 2026-06-19.

## Намерение (JTBD)
Владельцу Axon нужен **обзорный доступ** к пользователям, их проектам и базовым метрикам —
видеть, кто пользуется продуктом (демо руководству, модерация, понимание роста).

## Аудитория
**Единственный владелец** (ты). Гейт по `ADMIN_EMAIL` (env). Мультиадмина в v1 нет.

## Скоуп v1 — read-only, БЕЗ миграции БД
- **Гейт:** `isAdmin` = `session.user.email === ADMIN_EMAIL` (регистронезависимо). Не-админ на
  `/admin/*` → **404** (скрываем существование). Проверка на КАЖДОМ server-action И на странице.
- **`/admin/users`** — список юзеров: имя, email, дата регистрации, число проектов. Поиск по
  имени/email. **Мини-сводка** сверху: всего юзеров · всего досок · новых за 7 дней.
- **`/admin/users/[id]`** — детали: профиль (имя/email/дата) + список его досок (title, обновлено,
  есть ли публичная ссылка). Всё **read-only**.
- **Ссылка на `/admin`** в меню аватара — только админу.

## За рамками v1 → backlog
- **Роль в БД (admin/user) + назначение ролей** — после Урока 7 (нужно, но не сейчас; ADMIN_EMAIL
  покрывает single-owner). Решение пользователя 2026-06-19.
- Разрушительные действия (удалить/заблокировать юзера), поле `status` — позже.
- Открытие чужой доски в полном read-only-вьювере — позже (v1 показывает только список досок).
- Пагинация/виртуализация, фильтр по роли/статусу, `DataTable`/`Pagination` organisms в кит — позже.

## Критерии успеха
- Владелец (ADMIN_EMAIL) видит сводку + список юзеров + детали с их досками.
- Любой не-владелец (гость/обычный юзер) на `/admin/*` → 404; admin server-actions не отдают данные.
- `tsc`/`build` чисто; на проде после деплоя работает (ADMIN_EMAIL прокинут в compose→web.environment).

## Edge cases
Нет юзеров → «Пользователей нет»; ошибка → сообщение; длинный email → truncate; юзер без досок →
«Нет проектов»; поиск без результатов → «Ничего не найдено».

`ADMIN_EMAIL` — в `.env` (local), `.env.production` (server) И `docker-compose.yml → web.environment`
(иначе контейнер не увидит — грабли 2026-06-19). Не секрет, но env.

## Сложность: MEDIUM
5–7 файлов, новая **authz-поверхность**, без миграции/новых зависимостей. Тех-лид + security-review обязательны.

## Чеклист ревью (security — критично)
- `isAdmin` на КАЖДОМ admin server-action И на странице (не только в UI/меню).
- `/admin/*` не-админу → 404; server-actions не утекают данные (authz/IDOR).
- Сравнение email регистронезависимо (`toLowerCase`).
- Read-only: админка нигде не пишет/не удаляет в v1.
- Нет утечки секретов; Prisma параметризует (нет инъекций); поиск экранируется.

## Файлы (план)
- `lib/admin.ts` — `isAdmin(email)` / `requireAdmin()` (бросает/404 если не админ).
- `app/actions/admin.ts` — `adminListUsers(query?)`, `adminGetUser(id)`, `adminGetMetrics()` — все через `requireAdmin`.
- `app/admin/users/page.tsx` — сводка + список + поиск.
- `app/admin/users/[id]/page.tsx` — детали + доски.
- Ссылка на `/admin` в меню аватара (только админу).
- `docs/spec.md` + `docs/screens/admin-users.md` + `admin-user-details.md` — привести к v1-скоупу.
- env `ADMIN_EMAIL` (local + prod + compose).
