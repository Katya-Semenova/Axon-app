# Бриф — Живой AI-чат по данным (Урок 5, Шаг 1, фича «б»)

> Статус: **черновик на одобрение**. Код не начат. Дата: 2026-06-17.
> Процесс: `/new-feature` (интервью пройдено). Сложность: **COMPLEX** (~8 файлов, без миграции БД; переиспользует lib/ai + существующие store-действия).

## Намерение
Оживить чат-рейл в Data-режиме: пользователь спрашивает про свои данные словами —
ИИ отвечает по разобранной доске. Сейчас рейл — заглушка («AI chat coming soon»,
ввод обезврежен). Вторая (и последняя) фича Шага 1 после ИИ-извлечения инсайтов.

## Аудитория и ценность (из spec.md)
Те же роли. Ценность: быстро «поговорить с данными» без ручного копания — спросил
«какой канал лучший?» / «что выросло?» → получил внятный ответ по своим цифрам.

## Что строим (объём)

### 1. Советник + «Построить новый инсайт» (human-in-the-loop)
Чат **отвечает словами** по данным; и когда уместно — **предлагает достроить новый инсайт-график**
из данных пользователя и показывает кнопку **«Применить»**. Клик → новый инсайт+дата-сет ложится на
холст. ИИ сам ничего не строит без клика.

**Почему именно «построить новое», а не правки существующего:** сменить тип графика, удалить дата-сет,
редактировать строки пользователь **уже делает руками** (дропдаун типа на дата-сете, drill-in). Дублировать
это кнопкой в чате — мало толку. А вот **достроить срез, которого нет** — ценно: авто-разбор при загрузке
даёт ограниченный первый срез (~5 инсайтов), и в данных остаются углы, которые он не построил. Чат закрывает
этот «длинный хвост» по запросу.

**Связь с загрузкой (чтобы не путать):** загрузка файла = быстрый АВТО-черновик (фича «а», ~5 инсайтов сразу).
Чат = ПОТОМ, на холсте: разговор + дозаказ нового среза, которого в первой пятёрке не было. Это не дубль загрузки.

**Действие v1 — одно: `add-insight`** — построить новый инсайт+дата-сет по «рецепту» от ИИ
(title / narrative / chartType / dimension / metrics — та же форма, что `AIInsightPlan`). Применение
**переиспользует готовый `executePlan`** (1 инсайт) + `store.mergeBoardData` (он сам переименует id и допишет
узлы). Числа считаются из РЕАЛЬНЫХ данных (как в фиче «а»), не выдумываются.

### 2. Контекст = сводка доски (сырого файла уже нет)
После разбора сырая `ParsedTable` не хранится — в сторе только доска (инсайты/дата-сеты
с агрегированными числами + заголовки/нарративы + имена файлов). Поэтому ИИ получает
**компактную сводку доски** (то, что пользователь и так видит на холсте) + историю диалога
+ вопрос. Приватность: наружу уходит только эта сводка, не весь файл (принцип фичи «а»).

### 3. Ответ целиком (без стрима)
Пока ИИ думает — точки-тайпинг (как в build-чате), потом появляется полный ответ.
Переиспользуем текущий `lib/ai`-клиент (`complete`) и UI точек. Стрим по токенам — позже.

**Контракт ответа:** ИИ возвращает JSON `{ answer: string, action?: { type: "add-insight", plan: AIInsightPlan } | null }`.
`answer` — текст в чат; `action` (если есть и валиден) → кнопка «Применить построение». Валидируем на клиенте
перед показом кнопки: таблица-источник удержана, колонки рецепта существуют, chartType из 10.

### 2-bis. Удержание разобранной таблицы в памяти
Чтобы строить новый инсайт на реальных числах, стор держит последнюю `ParsedTable` в памяти
(`sourceTable`), проставляется при загрузке/добавлении файла. **В `BoardData` НЕ персистим** (приватность +
размер) — после перезагрузки «построить новое» недоступно до повторной загрузки файла (Q&A продолжает
работать). Мультифайл: держим последнюю таблицу (ограничение v1).

### 4. Персист — внутри документа доски (BoardData), без миграции
Лог чата кладём полем в `BoardData` (JSON-документ доски, ADR-003). Доска автосохраняется
(`BoardSync`) → **чат переживает перезагрузку/возврат** для вошедшего; гость — в памяти.
Отдельную таблицу `ChatMessage` НЕ заводим в v1 (миграция не нужна). Кап персиста — последние ~50 сообщений.

### 5. Доступ — только вошедшим (как фича «а»)
Серверный route с гейтом сессии (гость → 401) + rate-limit на пользователя. Гость в рейле
видит подсказку «войдите, чтобы спросить ИИ», ввод недоступен.

## За рамками (out of scope)
- **Автономные действия** (ИИ меняет холст сам, без кнопки «Применить») — отклонено как рискованное.
- **Правки существующего через чат** (сменить тип графика, удалить дата-сет, редактировать строки, собрать
  слайд) — это пользователь уже делает руками (дропдаун типа, drill-in); дублировать в чате не нужно.
- Стриминг ответа по токенам.
- Отдельная таблица `ChatMessage` + история на нескольких устройствах.
- Чат в Build-режиме (там свой мок deck-сборки — не трогаем).
- ИИ-перевод ответов (отвечает на языке данных/вопроса, как в spec i18n).

## Крайние случаи
- **Сбой ИИ / нет ключа / таймаут / лимит (429)** → у чата НЕТ rules-fallback (нельзя ответить
  правилами на свободный вопрос). Показываем сообщение-ошибку в чате («Не удалось получить
  ответ, попробуйте ещё») + кнопка повтора; история не рвётся.
- **Пустая доска** (нет инсайтов) → чат работает, но честно говорит «загрузите файл/данных пока нет».
- **Гость** → ввод недоступен, подсказка войти.
- **Нет удержанной таблицы** (зашёл в сохранённый проект после перезагрузки) → Q&A работает, но кнопку
  «Применить построение» не показываем; в промпте ИИ знает, что строить нечем → отвечает только словами.
- **ИИ предложил рецепт на несуществующие колонки / невалидный тип** → кнопку не показываем
  (валидация на клиенте против удержанной таблицы); остаётся текст ответа.
- **Применил** → кнопка → «Применено», повторное применение заблокировано; новый инсайт+дата-сет на холсте.
- **Длинная история** → в ИИ шлём последние N сообщений (кап контекста), персист тоже капим.
- **Длинный вопрос / инъекция в вопрос** → вопрос идёт как user-сообщение; ответ — текст (рендерим как текст, не HTML); системный промпт фиксирует роль (отвечать по данным, не выполнять посторонние инструкции).

## Документы (правило #1: сначала spec)

  отметить, что в v1 лог живёт в `BoardData` (ADR-003), не отдельной таблицей.

## Чеклист ревью (Часть 2)
- [ ] **Логика:** ответ по данным доски; история многоходовая; персист в доске переживает
  перезагрузку (вошедший); сбой → ошибка в чате, не молчание; гость → ввод закрыт.
- [ ] **Действие add-insight:** «Применить» только при валидном рецепте (таблица удержана, колонки есть,
  тип из 10); один клик строит инсайт на РЕАЛЬНЫХ числах (executePlan) и мержит; повтор заблокирован; ИИ сам не строит.
- [ ] **Безопасность:** ключ только сервер; route под сессией (гость→401); rate-limit `/api/ai/chat`;
  наружу только сводка доски (не сырой файл); ответ ИИ рендерится как текст (не HTML/markdown-инъекция);
  action валидируется на клиенте перед применением (не доверяем ссылкам ИИ вслепую); системный промпт ограничивает роль.
- [ ] **Архитектура:** переиспользует `lib/ai` (ADR-008), `checkRateLimit` и существующие store-действия;
  персист в `BoardData` (ADR-003, без миграции); плоская структура; build-чат не затронут.
- [ ] `npx tsc --noEmit` + `eslint` чисты; отдельный коммит на пункт; двуязычные ключи.

## Открытые вопросы (на потом, не блокируют)
- **Построение из нескольких файлов** — v1 держит последнюю таблицу; объединение источников — позже.
- **Персист таблицы для «построить» после перезагрузки** — сейчас не храним (приватность/размер); если
  понадобится строить в вернувшемся проекте — продумать хранение (напр. перепарсить из S3-файла).
- Лимит токенов на пользователя для чата — пока общий rate-limit; точная квота позже.
- Перенос лога в отдельную таблицу `ChatMessage` — если понадобится история кросс-устройств/аналитика.
- Стриминг ответа — улучшение UX позже.
