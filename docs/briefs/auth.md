# Бриф фичи: Вход и регистрация (auth)

> Ретроспективный бриф (Урок 4, Шаг 5) — для соответствия процессу `/new-feature`.
> Фича уже реализована и проверена на проде.

## Намерение
Дать пользователям аккаунты: регистрация → вход → выход, чтобы у каждого были свои
сохранённые проекты.

## Аудитория
Пользователи Axon (РФ, часто за VPN). Гость может работать без входа; вход нужен для
сохранения/шаринга/экспорта (см. spec.md, EC-4).

## Критерии успеха
- [x] Можно зарегистрироваться (email+пароль), войти, выйти.
- [x] Пароль хранится хешем (не открытым текстом).
- [x] Шапка показывает состояние входа.
- [x] Гость работает с холстом; авто-сохранение в БД — только для вошедших.

## Исключения (НЕ в этой фиче)
- Подтверждение email / письма аккаунта — Шаг 6.
- Разведение досок по пользователям («Мои проекты», IDOR) — Шаг 7.
- Защита входа (rate-limit, user-enumeration, флаги cookie) — Шаг 9.
- Соцвходы (Google и т.п.) и роль Admin — позже.

## Контекст проекта
Next.js 15 (App Router), Prisma 6 + PostgreSQL ([ADR-003](../decisions/ADR-003-data-layer.md)),
Better Auth ([ADR-004](../decisions/ADR-004-auth-library.md)). Экраны — на UI-ките
(`app/components/ui/`).

## Чеклист ревью
- [x] логика: регистрация/вход/выход, loading-состояние кнопок, ошибки показываются
- [x] безопасность (базовая): пароль хеширован, секрет `BETTER_AUTH_SECRET` в env (не в коде/git)
- [ ] безопасность (полная): IDOR/изоляция — Шаг 7; rate-limit/user-enum/cookie — Шаг 9
      (см. `docs/security-todo.md`)
