# Бриф — Шаг 7b: перенос гостевого холста в аккаунт

> Урок 4, Шаг 7b. Процесс: `/new-feature`. Сложность: MEDIUM. Дата: 2026-06-16.

## Намерение (простыми словами)
Гость работает без входа — холст живёт в памяти и пропадает при закрытии вкладки. Дать гостю сохранить свою работу: кнопка «Сохранить» → вход/регистрация в окне → текущий холст становится проектом в его аккаунте, ничего не теряется.

## Решения (одобрено пользователем)
1. **Кнопка «Сохранить»** в воркспейсе (явный гейт), не авто-баннер.
2. **Инлайн-окно** входа/регистрации (модалка), не переход на /login.
3. Перенос — **только по «Сохранить»** (не при обычном входе).

## Что построено
- `lib/store.ts` — экспорт `currentBoardData()` (снимок текущего холста); `BoardSync` переведён на него (убран дубликат).
- `app/actions/board.ts` — `createProjectFromData(data, title)`: создаёт доску сразу с данными гостя; владелец из серверной сессии.
- `app/components/AuthModal.tsx` — окно вход/регистрация (вкладки), `authClient.signIn/signUp.email`.
- `app/components/GuestSaveButton.tsx` — плавающая кнопка (видна только когда `boardId === null`): вошёл → сохраняем сразу; гость → окно; после входа перенос + тост «Проект сохранён».
- `app/page.tsx` — `ToastProvider` + `GuestSaveButton` в воркспейсе; `onSaved → setBoardId`.
- `docs/spec.md` — статус 7b.

## Крайние случаи
- Новый проект из гостевого холста = новая доска (не перезатирает существующие).
- Создание с данными ⇒ демо-сид не подменяет холст при привязке.
- Гость без входа сохранить не может (экшен вернёт null).
- Сбой/гонка сессии → тост «Не удалось сохранить, попробуйте ещё раз».

## За рамками
Шаринг/экспорт как гейты входа (фич ещё нет). Перенос при «обычном» входе через шапку. i18n текстов окна (RU-хардкод, как login/register — общий долг).

## Проверки
`tsc` чистый, `next build` успешный. Боевой тест на проде после деплоя: гость собирает холст → «Сохранить» → регистрация в окне → проект появляется в «Мои проекты», правки автосохраняются.
