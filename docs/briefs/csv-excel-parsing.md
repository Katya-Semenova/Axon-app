# Бриф: Реальный разбор CSV/Excel → инсайты и графики

> Фича через `/new-feature`. Одобрено 2026-06-17. Ядро продукта (spec.md → «Объём v1»).

## Намерение
Пользователь загружает CSV или Excel на главной → файл реально читается в браузере →
из его данных по правилам рождаются Insight-карточки и собираются DataSet-графики на
холсте (готовый «первый срез»), плюс пара слайдов. Заменяем демо-мок на данные
пользователя в главном сценарии продукта.

## Аудитория и успех (из spec.md)
Основатели / аналитики / консультанты: «загрузил файл — за секунды наглядный первый
срез своих данных». Успех = загрузил реальный CSV/Excel → увидел графики по своим
колонкам/строкам, а не демо.

## Движок инсайтов (по правилам, без ИИ)
1. Читаем файл → таблица: заголовки + строки, с определением типа каждой колонки
   (число / дата / категория / текст).
2. Определяем «измерения» (категории/даты) и «метрики» (числа).
3. Строим несколько инсайтов и подбираем тип графика по форме данных:
   - дата + число → временной ряд (Spline Area / Lollipop);
   - категория + число, мало категорий → Donut / Treemap;
   - категория + число, много → Treemap / Stacked Bar;
   - две числовые → Scatter; матрица чисел → Heatmap.
4. На каждый инсайт — DataSet + связь, раскладка на холсте, плюс несколько слайдов
   (архетип Chart) для мгновенного показа.

## Граница (сменный разъём)
Извлечение инсайтов — отдельный модуль `lib/insight-engine` с сигнатурой
`parsedTable → BoardData`. Позже сюда подключим ИИ (GigaChat / OpenRouter / прямой
API), не трогая разбор файла и холст. Выбор провайдера — отдельный ADR на шаге ИИ.
Заметка: OpenRouter — США, запросы пойдут с РФ-сервера (Selectel МСК) → возможны
проблемы доступа/оплаты; GigaChat — «родной» для РФ. Решим на шаге ИИ.

## За рамками (out of scope)
- ИИ-генерация инсайтов — отдельный будущий шаг.
- Хранение исходного файла в S3 (Project.sourceFiles) — будущее.
- PDF / картинки / SQL — «бета/упрощённо», не часть этой фичи.
- Ручное редактирование распознанных типов колонок.

## Крайние случаи (spec EC-1/EC-2)
- Битый / пустой / запароленный файл или > 50 МБ → рамка dropzone краснеет + причина.
- Разобран, но чисел нет → холст с текстовым инсайтом-резюме + подсказка (не тупик).
- Очень большой файл → ограничиваем число строк для графиков.
- Гость → всё в памяти; вошедший → автосейв в свой проект.

## Зависимости
Papaparse (CSV) + read-excel-file (Excel) — обе читают на клиенте. Установлены:
`papaparse@5.5.3`, `read-excel-file@9.2.0`, `@types/papaparse@5.5.2`.
Excel-парсер: выбран `read-excel-file` вместо SheetJS/`xlsx`. Причина — публичный
npm `xlsx` застрял на 0.18.5 с незакрытыми CVE (прототип-полюшн CVE-2023-30533,
ReDoS CVE-2024-22363; фиксы только на CDN SheetJS, не в npm). `read-excel-file`
свежий (9.2.0, поддерживается), легче (~1.3 МБ против ~7.5 МБ), с разбором типов
из коробки. Компромисс: читает только .xlsx, не legacy .xls/.ods → закрываем
понятной ошибкой dropzone (EC-1). Решение подтверждено пользователем 2026-06-17.

## Сложность
COMPLEX-lite — новые зависимости, ~6+ файлов, без миграций БД и auth.
Роли: исследователь → архитектор → кодер → ревью логики → ревью безопасности → тех-лид.

## Чеклист ревью
- Реальные данные пользователя на графиках (не демо) после загрузки.
- CSV и .xlsx оба читаются; кавычки/разделители/кодировка CSV не ломают.
- Битый/пустой/большой файл → понятная ошибка, не белый экран.
- Нет чисел → не пусто-молча, есть путь дальше.
- Гость и вошедший: память / автосейв в свой проект.
- Безопасность: парсинг на клиенте, без eval; защита от формульных инъекций Excel
  при отображении; ограничение размера/строк (защита от зависания вкладки).
