# Бриф: Добавление файла на холст (Шаг 11)

> Фича через `/new-feature`. Одобрено 2026-06-17. Развивает Шаг 10 (разбор CSV/Excel).
> Продуктовое решение пользователя: **Путь 1** — постоянная инфраструктура «merge файла
> в доску», вход — кнопка в чат-рейле. Позже тот же merge переиспользует живой ИИ-чат.

## Намерение
Пользователь уже на холсте (загрузил один файл или работает с доской) и хочет
**добавить ещё файл**, чтобы из него родились новые инсайты/графики **рядом** с
текущими — не теряя то, что уже есть, и не уходя на лендинг. Вход — кнопка
**«+ Добавить файл»** в левом чат-рейле.

## Аудитория и успех (из spec.md)
Основатели / аналитики / консультанты. Успех = находясь в воркспейсе, добавил второй
(третий…) файл → его инсайты, дата-сеты и слайды **дополнили** доску; ничего из
прежнего не пропало; путь очевиден (не через «новый проект» и не через лендинг).

## Механика (merge)
1. Кнопка «+ Добавить файл» → выбор файла (тот же скрытый `<input type=file>`-паттерн).
2. Переиспользуем Шаг 10: `parseFile` (lib/file-parsing) → `buildBoardData`
   (lib/insight-engine). Движок и парсер **не трогаем** — граница `parsedTable → BoardData`.
3. Новое действие в сторе **добавляет** узлы к текущей доске (в отличие от `hydrate`,
   который заменяет): новые insight/dataSet/connection/slide дописываются в
   `*ById` + `*Order` + `connections`, id и serial **со сдвигом** (без коллизий с
   уже сгенерированными `ins-up-1` и т.п.), позиции — **ниже** текущих узлов.
4. Сохранение: гость — в памяти; вошедший — текущий автосейв (`BoardSync`) подхватит.

## Чат-рейл (честная чистка заглушки)
- Убрать выдуманные сообщения («I've parsed 3 files… 47 tables…») и чужие имена
  файлов (`stripe_prod.sql` и т.п.) в `ChatRail.tsx`.
- Показывать **реальные** загруженные файлы доски → для этого вести список имён
  файлов (лёгкое поле `sourceFiles` в сторе/`BoardData`, согласуется с моделью
  `Project.sourceFiles[]` из spec). Пусто — нейтральное состояние, без вранья.
- Мёртвое поле ввода чата обезвредить (заглушка «ИИ скоро») до подключения GigaChat.

## Граница
- Переиспользуем как есть: `lib/file-parsing`, `lib/insight-engine`, тосты (`ToastProvider`).
- Не трогаем: разбор файла, движок инсайтов, рендер графиков/холста, логику автосейва.
- Живой ИИ-чат — отдельный будущий шаг; здесь только обезвреживаем заглушку.

## За рамками (out of scope)
- Реальный ИИ-чат (GigaChat) и добавление файла «через разговор».
- Управление файлами: удалить файл и его узлы группой, дедупликация повторной загрузки.
- Хранение самих файлов в S3 (`Project.sourceFiles` как реальные файлы) — позже.
- Изменение правил движка/типов графиков.

## Крайние случаи
- **EC-1 (битый/пустой/большой/не тот формат) при добавлении в воркспейсе:** нет
  dropzone → показываем причину **тостом** (красный), доска не меняется.
- **EC-2 (нет чисел):** добавляем текстовый инсайт-резюме к доске (не тупик).
- **Повторная загрузка того же файла:** допускаем дубли (без дедупликации в v1).
- **Гость на демо-сиде:** merge добавляет узлы к демо-доске (тоже валидно).
- **Очень большой файл:** тот же лимит 50 МБ/строк из Шага 10.

## Зависимости
Новых нет — переиспользуем Шаг 10 + существующие тосты и UI-кит.

## Сложность
MEDIUM — ~4–6 файлов (store-действие + поле sourceFiles, ChatRail, общий обработчик
добавления, словари RU/EN, spec.md), без миграций БД и новых зависимостей.
Роли: кодер → ревью логики → ревью безопасности → тех-лид.

## Чеклист ревью
- Добавление **дополняет** доску, прежние узлы целы; новые не накладываются на старые.
- Гость (память) и вошедший (автосейв) — оба пути работают.
- Чат-рейл показывает **реальные** файлы; фейкового текста и чужих имён нет; ввод обезврежен.
- Ошибка разбора в воркспейсе → понятный тост, не белый экран, доска не портится.
- Файл без чисел → текстовый инсайт добавлен.
- Безопасность: парсинг на клиенте без eval; формул-инъекции/лимиты уже закрыты в движке (Шаг 10).
- `tsc` чист; `spec.md` обновлён (сценарий «добавить ещё файл» + статус sourceFiles).
