# Бриф — ИИ-извлечение инсайтов (Урок 5, Шаг 1)

> Статус: **черновик на одобрение**. Код не начат. Дата: 2026-06-17.
> Процесс: `/new-feature` (интервью пройдено). Сложность: **COMPLEX**.

## Намерение
Сделать ИИ настоящим ядром продукта: «загрузил файл → **ИИ** достаёт инсайты и
собирает дата-сеты», вместо текущего движка **по правилам** (`lib/insight-engine`).
Граница `ParsedTable → BoardData` спроектирована как «сменный разъём» — встаём в неё.

Первая фича Шага 1. Живой AI-чат — следующая фича, **не сейчас**.

## Аудитория и ценность (из spec.md)
Основатели / аналитики / консультанты / product-маркетинг. Ценность: «Your data, in
plain English» — ИИ быстро даёт готовый первый срез + **инсайт словами**, пользователь
правит под себя. (spec.md → Продукт, Ключевая ценность.)

## Что строим (объём)

### 1. Гибридная роль ИИ (целостность данных)
ИИ делает интеллектуальную часть, код — арифметику:
- **ИИ решает:** какие колонки интересны, как сгруппировать → **состав дата-сетов**;
  тип графика (из 10 активных); **заголовок**; **нарратив-инсайт словами** (plain English).
- **Код считает:** фактические числа строк из реальных данных по «рецепту» от ИИ
  (напр. ИИ: «выручка по регионам, treemap, топ-10» → код берёт настоящие суммы из файла).
- **Почему так:** график показывает реальные цифры пользователя, ИИ **не печатает числа руками**
  (единственное, что галлюцинирует и убивает доверие к дата-продукту).
- **Нарратив протекает в слайд:** текст инсайта кладётся в `narrative` → присутствует на
  слайде (см. [[project_slide_archetypes]], основной инсайт на слайде).

### 2. Провайдер-агностичный слой `lib/ai/`
- Интерфейс LLM-клиента + адаптеры. **Дефолт-адаптер — OpenRouter** (доступ к Claude/GPT
  для демо MVP; дефолт-модель — актуальная Claude, напр. `claude-sonnet-4-6`, конфигом).
- **GigaChat-адаптер — как опция** (заготовка). Решение GigaChat↔OpenRouter откладываем:
  это смена конфига/адаптера, не переписывание.
- Ключи — **только сервер** (`OPENROUTER_API_KEY` и т.п. в `.env*`, не в git). Владелец
  вписывает значение сам.

### 3. Поток данных (приватность: шлём только схему + выборку)
1. Клиент: `parseFile` → `ParsedTable` (полная таблица **остаётся в браузере**).
2. Клиент: профиль колонок + N образцов строк → POST на серверный route.
3. Сервер (`/api/ai/extract`): гейт сессии (гость → 401), rate-limit, вызов `lib/ai`
   → структурный **план**: `insights[] { title, chartType, recipe, narrative }`. Валидация формы.
4. Клиент: 200 → исполняет план «рецептов» против **полной** таблицы (переиспользуя
   билдеры `lib/insight-engine`) → `BoardData` с реальными числами. Ошибка/таймаут/401 →
   **fallback на правила** `buildBoardData(table)`.
5. Вошедший → `createProjectFromData(board)` (автосейв). Гость → сразу правила (без ИИ).

### 4. Доступ — только вошедшим
ИИ-разбор требует входа (лимит токенов на юзера, контроль расхода/абьюза). Гость получает
**rules-разбор** (текущее поведение сохраняется) или приглашение войти. Точки:
`LandingPage.tsx`, `ChatRail.tsx`.

### 5. Синхронно (спиннер), EC-3 как loading
Ждём ответ ИИ с loading-состоянием (skeleton/спиннер), **без фоновой очереди**. EC-3
«generating» = loading-состояние, не асинхронное событие. (Async + центр уведомлений —
отдельная будущая фича, см. бэклог.)

## За рамками (out of scope)
- Живой AI-чат по данным (следующая фича Шага 1).
- Асинхронная очередь + центр уведомлений (бэклог; требует async-события).
- Реальный разбор PDF/картинок/SQL через ИИ (остаётся Beta-путь).
- Финальный выбор GigaChat vs OpenRouter (отложен; агностичность это позволяет).
- ИИ-перевод/локализация инсайтов (контент — на языке данных, как в spec i18n).

## Крайние случаи
- **Нет ключа / таймаут (напр. 30с) / ошибка API / rate-limit** → fallback на правила;
  пользователь всё равно получает доску (опц. тихая плашка «базовый разбор»).
- **ИИ вернул невалидный план** (несуществующая колонка / chartType не из 10 / метрика
  не числовая) → валидируем по-инсайтно, битые отбрасываем; все битые → fallback на правила.
- **Нет числовых колонок (EC-2)** → ИИ пишет текстовое summary; иначе rules-summary.
- **Большой файл** → ИИ-стоимость ограничена (шлём только схему + кап образцов); числа
  считаются из полной (уже капнутой парсером) таблицы локально.
- **Гость** → ИИ недоступен, путь правил без изменений.

## Чеклист ревью (Часть 2)
- [ ] **Логика:** числа строк = из реальных данных, не от ИИ; нарратив в слайде; 10 типов графиков; fallback на правила работает.
- [ ] **Безопасность:** ключ только сервер; route под сессией (IDOR/гость→401); rate-limit `/api/ai/*`; prompt-injection (вывод ИИ = валидируемый JSON, не исполняется; имена колонок уже нейтрализованы от формул); нарратив рендерится как текст, не HTML.
- [ ] **Архитектура:** агностичность (смена провайдера = конфиг); граница `ParsedTable → BoardData` сохранена; не противоречит ADR-003 (data-layer); плоская структура (НЕ FSD).
- [ ] `npx tsc --noEmit` чист; отдельный коммит на пункт.
