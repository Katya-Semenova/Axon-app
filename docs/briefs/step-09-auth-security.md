# Бриф — Шаг 9: защита входа (auth-security)

> Урок 4, Шаг 9. Сложность: MEDIUM (1 файл кода, без миграции). Дата: 2026-06-16.

## Намерение
Закрыть накопленные security-долги аутентификации: перебор пароля, спам-регистрации, «бомбинг» письмами сброса.

## Что сделано
- **Rate-limit** в Better Auth (`lib/auth.ts`, `rateLimit`): включён; базовый лимит мягкий (100/10с), чувствительные пути строгие — вход `/sign-in/email` 10/мин, регистрация `/sign-up/email` 5/мин, сброс `/request-password-reset` `/forget-password` 3/мин, `/reset-password` 5/мин. По **реальному IP** (nginx шлёт `X-Forwarded-For` — проверено). Хранение — в памяти (без миграции; сбрасывается при передеплое — для нашего масштаба ок).
- **Cookie сессии** — HttpOnly + Secure (HTTPS) + SameSite=lax по умолчанию Better Auth (изменений не требуется, зафиксировано).
- **User-enumeration** — вход обезличен («Invalid email or password»), `/forgot-password` нейтрален (Шаг 6); регистрация по природе сообщает о занятом email (принято; перебор ограничен rate-limit).

## За рамками
Полный security-check всего бэкенда — Шаг 13. Перенос rate-limit в БД (переживать передеплой) — при необходимости позже.

`tsc` чистый, `next build` успешный. На проде после деплоя: серия быстрых попыток входа → `429 Too Many Requests` после лимита.
