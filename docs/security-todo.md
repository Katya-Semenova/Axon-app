## Из Шага 5 (auth)
- ✅ **IDOR / изоляция досок — ЗАКРЫТО на Шаге 7.** Серверные экшены в
  `app/actions/board.ts` (`getBoard / saveBoard / listProjects / createProject /
  deleteProject / renameProject`) берут владельца **только из серверной сессии**
  (`auth.api.getSession`) и проверяют `Board.ownerId === userId`; чужая/несуществующая
  доска → null/false (как 404). Доски разведены по пользователям.
- 🟡→✅ **User-enumeration (Шаг 9) — частично закрыто.** Вход отвечает обезличенно
  («Invalid email or password» — не выдаёт, существует ли email). `/forgot-password`
  нейтрален (Шаг 6). **Регистрация** по своей природе сообщает, занят ли email (иначе
  нельзя зарегистрироваться) — осознанно принято; перебор почт ограничен rate-limit'ом.
- ✅ **Защита входа — ЗАКРЫТО на Шаге 9.** Rate-limit в Better Auth (`lib/auth.ts`):
  вход 10/мин, регистрация 5/мин, сброс пароля 3/мин (по реальному IP — nginx шлёт
  X-Forwarded-For). Cookie сессии: HttpOnly + Secure (HTTPS) + SameSite=lax (дефолт
  Better Auth). Хранение лимита — в памяти (сбрасывается при передеплое; для нашего
  масштaба ок).

## Из Шага 6 (письма)
- ✅ **User-enumeration на `/forgot-password` — учтено.** Экран всегда отвечает нейтрально
  («если аккаунт есть — письмо отправлено»), наличие email не раскрывается. (Унификация
  сообщений на входе/регистрации — по-прежнему Шаг 9.)
- ✅ **Rate-limit сброса/отправки писем — ЗАКРЫТО на Шаге 9.** `/request-password-reset`,

- ✅ `RESEND_API_KEY` — только в env (вне git/чата), резерв в Bitwarden; в логах не светится.
