  **Решено 2026-06-17: делать в САМОМ КОНЦЕ проекта, после Урока 7** (отдельной сессией) — или не делать.
  Проект собран плоско (`app/` — роуты+страницы, `lib/` — логика/данные, `app/components/` — по экранам);
  Урок 2 (`lessons/lesson-02-design/prompts/04-fsd-architecture.md`) предписывает FSD в `src/`.
  Функционально не мешает; выгода FSD — для больших команд/кодовых баз, у нас соло-проект.
  **Как делать, если возьмёмся (чтобы не больно):** по шагам, не «всё сразу», и только ПОСЛЕ тестов
  (Урок 5) как подстраховки — `shared` → `entities` → `features`/`widgets` по областям; маршруты Next
  (`app/`) держать тонкими; **единый Zustand-стор резать по слайсам — в последнюю очередь или вовсе нет**
  (самая рискованная часть). Каждый шаг: `tsc` + тесты + коммит.
  **Боль:** «всё сразу» больно (импорты ломаются разом + конфликт `app/` Next vs FSD); по шагам с тестами —
  терпимо, но это работа на несколько сессий ради нулевой выгоды для пользователя.
  Перевод промтов уроков FSD→Axon: `entities`→`lib/types.ts`+`app/actions/`, `features`→`app/components/*`,
  `shared/ui`→`app/components/ui/`, `shared/lib`/`shared/db`→`lib/`, `src/app`→`app/`,
  `src/middleware.ts`→`middleware.ts`.

  - *Ярус 2 — структурное, ОДНИМ фокус-проходом после Урока 5 (лучше с тестами):* слияние «Формат»;
    редактируемый текст + залоченная раскладка; «+слайд»-пикер; Present-очистка; **схлопывание полей

  - *Ярус 3 — AI-зависимое:* «AI-тема по образцу» (Pinterest/скриншот → Тема) — **только после AI-инфры Урока 5**.
  **Рекомендация:** основной проход (Ярус 2) — отдельной сессией сразу после Урока 5; Ярус 1 — можно раньше

## Холст / связи и загрузка — UX (2026-06-17)
- **Показать пользователю предупреждение об усечении файла.** Баг данных #1 (ревью Шага 11)
  починен — `truncatedRows` теперь честный, НО поле нигде не показывается в UI. Добавить
  тост/нотис «Показаны первые 5000 строк из N» при разборе (`LandingPage` + `ChatRail`),
  когда `truncatedRows > 0`. Иначе усечение по-прежнему молчит для пользователя.
- **Связь инсайт↔датасет — тянуть в обе стороны.** Сейчас связь тянется только инсайт→датасет;
  обратно (датасет→инсайт) не работает и сбивает с толку. Сделать жест перетаскивания
  ДВУНАПРАВЛЕННЫМ: хватаешь любой из двух узлов — система сама ориентирует связь как
  `Insight→DataSet` (данные текут в одну сторону, меняется только удобство жеста). Пара
  одинаковых типов (инсайт→инсайт / датасет→датасет) — просто no-op, без предупреждения.
  Решено в обсуждении (предупреждение «нельзя» отклонено как тупиковый UX).
  Затрагивает drag-логику `Canvas.tsx` + `addConnection` в `store.ts`.

- **Пустой стейт чат-инпута для гостя.** Сейчас неавторизованный видит задизейбленный
  инпут чата без объяснения, почему нельзя задать вопрос («немое» поле). Добавить понятную
  надпись-CTA в самом инпуте / placeholder, напр. «Зарегистрируйтесь, чтобы спросить ИИ о
  ваших данных» (вместо молчаливого disabled). Наблюдение из приёмки Урока 5 (2026-06-19).
  Файл: `app/components/.../ChatRail.tsx`.

- **Вход из холста = тупик (сценарий логина).** Чтобы залогиниться, гость вынужден
  возвращаться на лендинг — неудобно. Плюс кнопка «Сохранить» на холсте не объясняет, что делает
  (сохранить → требует входа?). Продумать сценарий: явный «Войти» прямо на холсте и/или понятный
  смысл «Сохранить» для гостя. Наблюдение из прод-проверки Урока 5 (2026-06-19).

- **Умная раскладка холста по файлам + fit-to-view (крупная фича, Блок 2).** Сейчас новые
  инсайты/датасеты уходят стопкой вниз; авто-пан (2026-06-19) подвозит к первому новому, но всё
  разом не видно, а при многих узлах мелко (зум ~20%). Идея (пользователь, 2026-06-19): делить
  вьюпорт на ячейки ПО ФАЙЛАМ — 1 файл → центр; 2 → пополам (слева/справа); 3 → на трети; 4 →
  квадранты; каждый блок = инсайты+датасеты своего файла. Плюс **авто-масштаб (fit-to-view)**:
  зум/пан так, чтобы всё помещалось. Требует: маппинг узел→файл-источник (хук: общий token-префикс
  id из `mergeBoardData`), лейаут по регионам, обработку >4 файлов, расчёт bounding box + fit.
  Связано с авто-паном (`focusNodeId`) и наблюдениями #2/#4 (спавн за вьюпортом).

- **Гранулярность инсайт↔датасет (#1, продукт).** Один файл сейчас даёт несколько похожих
  графиков (напр. 3 доната одного разреза Region). Рассмотреть «меньше, но богаче»: один датасет

  Блок 2 (правка ИИ-извлечения + промпта). Наблюдение приёмки Урок 5 (2026-06-19).
- **«+ Новый дата-сет» = пустой тупик (#3).** Кнопка плодит пустой узел, непонятно зачем. Либо
