# Словарь терминов AXON

> Простые пояснения слов, которые встречаются в работе. Каждый новый термин —
> сразу простыми словами, без жаргона.

- **Персист (persist)** — данные сохраняются так, что остаются на месте после
  перезагрузки страницы или закрытия браузера (записаны в базу данных, а не висят
  временно в памяти). «Проверить персист» = нажать F5 и убедиться, что ничего не пропало.
- **Хук (hook)** — действие, которое Claude Code запускает сам, автоматически, в нужный
  момент (например, после правки файла показать напоминание). Не ты и не ИИ его вызывают.
- **Cookie (куки)** — маленький файлик, который сайт кладёт в браузер, чтобы помнить, что
  ты вошла. Флаги `HttpOnly`/`Secure` — настройки защиты этого файлика.
- **IDOR** — дыра в безопасности, когда один пользователь может открыть чужие данные,
  подставив чужой номер/ссылку. «IDOR закрыт» = чужое посмотреть нельзя.
- **Инкогнито** — отдельное окно браузера без твоего входа и истории; удобно проверять,
  что видит посторонний человек.
- **Бэклог (backlog)** — список отложенных доработок: что хотим сделать, но не сейчас.
- **Ветка (branch)** — отдельная копия кода «вбок» от основной. В ней можно делать что угодно,
  основная версия и живой сайт не трогаются. Получилось — вливаешь обратно; нет — выбрасываешь ветку.
- **Коммит (commit)** — сохранённая точка в истории кода с подписью «что я тут поменяла». К ней
  всегда можно вернуться. Как «сохранить версию» с комментарием.
- **Мёрж (merge)** — влить изменения из одной ветки в другую (обычно из рабочей в основную).
- **Откат (rollback)** — вернуть всё как было, отменить изменения. С веткой откат = просто
  переключиться обратно на основную.
- **Фича-флаг (feature flag)** — выключатель в коде. Новая фича лежит за ним и по умолчанию выключена.
  Старый путь работает как раньше; включить новое — одна строчка.
- **Тайм-бокс (timebox)** — заранее заданный лимит времени на задачу. «Тайм-бокс 75 минут» = работаем
  максимум 75 минут, потом стоп. Защита от залипания.
- **Спайк (spike)** — быстрый черновой эксперимент-разведка: проверить, что подход вообще рабочий.
  Не финальный код.
- **Рендерер (renderer)** — кусок кода, который рисует график на экране. У AXON есть свой рендерер;
  Highcharts — второй на выбор.
- **Highcharts** — готовая библиотека графиков: много типов диаграмм и интерактивность «из коробки».
- **TypeScript-проверка (`npx tsc --noEmit`)** — проверка кода на ошибки типов без запуска. Должна быть
  чистой перед каждым коммитом.
- **SSR / гидрация** — сайт сначала собирается на сервере (SSR), потом «оживает» в браузере (гидрация).
  Некоторые библиотеки графиков умеют рисовать только в браузере — их помечают «только клиент».
- **FSD (Feature-Sliced Design)** — способ раскладывать код по слоям: общее → сущности → фичи →
  страницы. Правило: импорты идут только «вниз» (страница знает про фичи, фичи про общее, но не наоборот).
- **Монорепо (monorepo)** — один репозиторий (одна папка с git), в котором лежат несколько приложений
  сразу. У нас в `development/`: сервис, лендинг и общий пакет — вместе, но собираются по-отдельности.
- **База данных (БД)** — место, где данные хранятся постоянно (таблицы). У нас — PostgreSQL.
- **ORM** — прослойка между кодом и базой: пишешь на обычном коде (объекты), а ORM сам превращает это
  в запросы к таблицам. У нас ORM — **Prisma**.
- **Prisma** — конкретный ORM для нашей БД: описываешь модели в одном файле (`schema.prisma`), а он даёт
  готовый код для чтения/записи.
- **Миграция (migration)** — записанное изменение структуры базы (добавили таблицу/колонку). Версии
  схемы, которые можно накатить по порядку. Лежат в `prisma/migrations/`.
- **Better Auth** — готовая библиотека входа в аккаунт (регистрация, пароль, сессии). Избавляет от
  написания авторизации с нуля.
- **Resend** — сервис отправки писем (сброс пароля, приветствие и т.п.).
- **S3 / объектное хранилище** — «облачная папка» для файлов (у нас — аватары, загрузки). Файлы лежат
  не в базе, а отдельно; у нас провайдер — Selectel.
- **ADR (Architecture Decision Record)** — коротко записанное архитектурное решение: что выбрали и
  почему. Лежат в `docs/decisions/`. Нужны, чтобы через месяц помнить причину выбора.
- **Rate-limit (лимит запросов)** — ограничение «не больше N раз за время» (например, к ИИ), чтобы
  сервис не перегружали и не злоупотребляли.
- **Server actions (серверные действия)** — функции Next.js, которые пишутся как обычный код, но
  выполняются на сервере (лежат в `app/actions/`). Клиент вызывает их напрямую, без ручного API-роута.
