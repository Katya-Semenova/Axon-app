# Архитектура Axon (карта по коду)

> **Обновлено 2026-07-03** под текущее состояние проекта. Раньше документ описывал Урок 2
> (не было БД, API-роутов, авторизации и секретов) — сейчас всё это есть, поэтому разделы
> ниже переписаны и добавлены новые. Документ — источник для презентации разработчикам,
> поэтому отражает реальность, а не план.
>
> **Решение по FSD остаётся в силе.** Рецепт Урока 2 разворачивает `src/` по 6 слоям Feature-Sliced
> Design **с нуля**. Axon — уже собранное, задеплоенное приложение (Next.js App Router). Мы **не
> переносим код физически** в `src/` и по слоям (это сломало бы рабочий прод), а **документируем
> существующую структуру в терминах FSD**: какая папка играет какую роль. Это сверка дисциплины
> слоёв, а не реструктуризация. Рефакторинг здесь не предлагается.

**FSD** — Feature-Sliced Design, способ раскладывать код по слоям (общее → сущности → фичи → страницы),
где импорты идут только «вниз». *(Термин — в [glossary.md](glossary.md).)*

## Монорепо и деплой

Код живёт в **монорепо** (один репозиторий с несколькими приложениями) — папка `development/`
(npm-workspace):

| Пакет | Что это | Технология |
|---|---|---|
| `development/apps/app` | **Сервис** — само приложение AXON (холст, слайды, ИИ, вход) | Next.js 15, адрес `/ai-studio` |
| `development/apps/landing` | **Лендинг** — публичная витрина | Next.js 16, адрес `/` |
| `development/packages/ui` | Общий пакет `@axon/ui` — токены бренда | — |

**Важно про пути:** дальше в документе все пути даны **относительно `development/apps/app/`**
(сервис), если не сказано иное.

**Деплой** — оба приложения собираются в Docker и живут на одном VPS за nginx (`/` → лендинг,
`/ai-studio` → сервис). Подробности деплоя — в [memory/infrastructure.md](memory/infrastructure.md),
здесь не дублируем. Рендер графиков можно переключить на Highcharts за фича-флагом (см. «Слой графиков»).

## Главный вывод (дисциплина импортов)

Код **следует FSD-логике направления импортов**, хотя физически разложен по `app/`, а не по `src/`
(проверено grep'ом по `development/apps/app`, 2026-07-03):

- ✅ **UI-кит чист** — `app/components/ui/` (Button/Input/Card/Badge/…) не импортит ни фичи, ни
  бизнес-домен. Это настоящий `shared/ui`.
- ✅ **Фичи не импортят друг друга** крест-накрест (canvas не тянет chat и т.д.) — связь только через
  общий store.
- ✅ **State — единый центр** (`lib/store.ts`, Zustand), его читают все фичи + страница-оркестратор.
  Импорты идут «вниз», к общему слою.
- ⚠️ **Одно расхождение:** 4 «ui»-компонента знают домен (см. «Расхождения», п. 5).

## Маппинг слоёв FSD → реальные папки Axon

*(Пути относительно `development/apps/app/`.)*

| Слой FSD | Что регулирует | Где в Axon | Заметка |
|---|---|---|---|
| `app/` (роутинг, провайдеры, layout) | Вход, обвязка, глобальные стили | `app/layout.tsx` (шрифты next/font, `<html>`), `app/page.tsx` (оркестратор), `app/globals.css` | Канонично для App Router |
| `pages/` (страница на маршрут) | Контент каждого экрана | **Нет папки** для холста. Рабочая зона — машина состояний: вью-состояния в store (`view`/`mode`/оверлеи). Но реальные роуты уже есть: `/settings`, `/login`, `/register`, `/admin/*`, `/p/[id]`, `/api/*` | См. п. 2 расхождений |
| `widgets/` (крупные блоки обвязки) | Header/Sidebar-уровень | `ChatRail`, `ModeTabs`, `PresentationStructure` — собираются в `page.tsx` | Обвязка живёт в оркестраторе |
| `features/` (действия пользователя) | Фича-слайсы | `app/components/{landing, canvas, chat, presentation, build}/` | Каждая папка = слайс; друг друга не импортят ✅ |
| `entities/` (бизнес-сущности) | Доменная модель | `lib/types.ts` (Insight/DataSet/Slide/Deck/Connection), `lib/store.ts` (state + действия), `prisma/schema.prisma` (модели БД) | Модель централизована в `lib/`, не разбита по `entities/<x>/` — см. п. 3 |
| `shared/ui/` (UI-кит без домена) | Примитивы | `app/components/ui/` (Button/Input/Card/Badge/Chip/Avatar/Modal/Toast/…) | Чистый, на токенах ✅ |
| `shared/lib` | Утилиты, слои-адаптеры | `lib/charts.ts`, `lib/ai/`, `lib/auth.ts`, `lib/email.ts`, `lib/storage.ts`, `lib/db.ts`, `lib/insight-engine/`, `lib/file-parsing/` | «Серверные» слои тоже сюда |
| `shared/config` | Токены/константы | `app/components/ui/tokens.ts`, `globals.css @theme`, `packages/ui` (`@axon/ui`) | Источник — [DESIGN.md](DESIGN.md) |

## Направление импортов (проверено grep'ом 2026-07-03)

```
app/page.tsx (оркестратор)
   └─→ widgets (ChatRail, ModeTabs, PresentationStructure)
        └─→ features (canvas, chat, landing, presentation, build)
             └─→ entities/shared (lib/store, lib/types, lib/ai, components/ui)
```

- `app/components/ui/*` **не импортит** ничего из `{canvas,chat,landing,presentation,build}` → кит
  ничего не знает о фичах. ✅
- `app/components/canvas/*` **не импортит** соседние фичи. ✅
- `lib/store.ts` читают все фич-папки + `page.tsx`. Импорт «вниз». ✅

## Расхождения с каноническим FSD (осознанные, НЕ баги)

1. **`app/` в корне, не `src/`.** Next.js App Router штатно живёт в корневом `app/`. Переезд в `src/`
   ничего не даёт, кроме риска сломать прод. Оставляем.
2. **Нет `pages/` на каждый экран холста.** Рабочая зона (холст/слайды/показ) — машина состояний
   (`view`/`mode`/оверлеи), зафиксировано в [screens-map.md](screens-map.md). При этом «настоящие»
   роуты (вход, настройки, админка, публичная дека, API) уже есть — это обычные страницы App Router.
3. **Доменная модель централизована.** Сущности — в `lib/types.ts`, state — в `lib/store.ts`, а не в
   `entities/<x>/`. Для приложения такого размера один store проще; дробить преждевременно.
4. **Public API через `index.ts` нет** — импорты прямыми путями (`@/app/components/...`). При росте
   можно добавить barrel-файлы, сейчас избыточно.
5. **4 компонента в `ui/` знают домен** — `ChartTypeDropdown`, `LayoutDropdown`, `ModeToggle`,
   `ModeTabs` импортят `lib/store`/`lib/types`. По строгому FSD они НЕ `shared/ui` — это уровень
   `features`/`entities`, исторически в папке `ui/`. **Флаг на чистку** (не срочно). Чистый кит
   (Button/Input/Card/…) этим не затронут. *(Было 5; `ComboLayoutDropdown` удалён.)*

## База данных

**PostgreSQL** (реляционная БД) + **Prisma** (ORM — прослойка, что превращает таблицы БД в объекты
кода; термины — в [glossary.md](glossary.md)).

- **Схема:** `prisma/schema.prisma` — **6 моделей:** `User`, `Board`, `ShareLink`, `Session`,
  `Account`, `Verification`. (Session/Account/Verification — служебные таблицы входа, их ведёт Better Auth.)
- **`Board` хранит доску одним JSON-документом** (поле `data Json`) — весь холст пользователя как один
  объект, а не разложенный по таблицам. Осознанное решение — [ADR-003](decisions/) (ADR = записанное
  архитектурное решение).
- **Где живёт БД:** локально — **Neon** (Postgres в облаке), на проде — **Postgres в docker-compose**.
- **Клиент:** `lib/db.ts` (Prisma client). Миграции (версии схемы) — `prisma/migrations/`.

## Авторизация и письма

- **Вход — Better Auth** (`lib/auth.ts`): email + пароль, через `prismaAdapter` (пишет в те же 6 моделей).
  Роут — `app/api/auth/[...all]/route.ts`. Клиент — `lib/auth-client.ts`.
- **Письма — Resend** (`lib/email.ts`): системные письма (сброс пароля, смена пароля, приветствие).
  Шаблоны — `emails/` (React Email: `Layout`, `Welcome`, `PasswordReset`, `PasswordChanged`).
- **Файлы (аватары, загрузки) — S3** (Selectel Object Storage): `lib/storage.ts`, роут `app/api/files`.

## Слой ИИ

Провайдер-**агностичный** слой `lib/ai/` — код не привязан к одному ИИ-провайдеру ([ADR-008](decisions/)):

- **Адаптеры:** `openrouter.ts` (провайдер по умолчанию), `gigachat.ts` (опция); общий тип — `types.ts`,
  сборка — `index.ts`.
- **Защита:** `rate-limit.ts` — лимит запросов к ИИ (чтобы не злоупотребляли).
- **Роуты:** `app/api/ai/extract` (файл → инсайты) и `app/api/ai/chat` (чат по данным доски).
- **Ключи ИИ — только на сервере** (в роутах), в браузер не попадают.
- **Fallback:** если ИИ недоступен, инсайты строят правила `lib/insight-engine/` (детерминированно).

## API-роуты (`app/api/*`) и серверные действия

- **`app/api/`:** `ai` (extract/chat), `auth` (Better Auth), `avatar` (загрузка фото), `demo`
  (демо-вход для стенда, за флагом), `files` (S3-файлы).
- **`app/actions/`** (Next server actions — серверные функции, вызываемые из клиента напрямую):
  `board.ts` (сохранение/загрузка досок), `share.ts` (публичные ссылки), `admin.ts` (админ-действия).
- **`app/admin/users`** — read-only админ-панель (гейт по email, не-админ → 404).
- **Публичная дека:** `app/p/[id]/` — доска по приватной ссылке-токену.

## Слой графиков (родной + Highcharts за флагом)

- По умолчанию графики рисует **родной SVG-рендерер** AXON — `app/components/ChartRenderer.tsx`
  (+ мини-превью `MiniChart.tsx`). Значение `RENDER_ENGINE = 'native'` в `lib/renderEngine.ts`.
- **Спайк:** bar-графики можно пустить через **Highcharts** (`app/components/HighchartsRenderer.tsx`) —
  сменой одной строки на `'highcharts'`. По умолчанию выключено, старый путь не трогается. *(Спайк,
  фича-флаг — в [glossary.md](glossary.md).)*

## Секреты и переменные окружения

> **Раздел переписан 2026-07-03.** Раньше здесь стояло «у Axon нет ни одного секрета» — это устарело
> полностью: появились БД, авторизация, письма, файлы и ИИ, у каждого свой секрет.

**Секреты теперь есть.** Все — в `.env`-файлах, которые **не лежат в git** (`.gitignore` прячет `.env*`).
Конкретные значения здесь не приводим — только где какой:

| Что | Переменные (имена) | Где |
|---|---|---|
| База данных | `DATABASE_URL` | dev — Neon; prod — `.env.production` |
| Вход (Better Auth) | `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` | разные в dev и prod |
| Письма (Resend) | `RESEND_API_KEY` | только prod |
| Файлы (S3) | `S3_*` (endpoint/region/ключи/бакет) | Selectel Object Storage |
| ИИ | ключ провайдера + `AI_MODEL` | только сервер |
| Аналитика | `NEXT_PUBLIC_YM_ID` | публичный (впекается в HTML) |

**Правило:** реальные значения — на сервере в `.env.production` (+ бэкап в менеджере паролей), НЕ в git,
НЕ в чат. `NEXT_PUBLIC_*` — не секрет (уходит в браузер на сборке). Любая новая переменная — сперва
в `.env.example` (имя без значения), потом в код.
