# Экран: Админка — список пользователей

**URL:** `/admin/users` (под `basePath` → `/ai-studio/admin/users`)
**Доступ:** только админ (email ∈ `ADMIN_EMAIL`). Не-админ (гость/пользователь) → **404**
(`notFound()` — скрываем существование админки). Серверный рендер, `force-dynamic`.

Файлы: `admin/users/page.tsx` · данные через server-actions `adminGetMetrics`, `adminListUsers(q)`
(каждое под `requireAdmin`). Вход на экран — ссылка «Админка» в `/settings` (видна только админу).

---

## Состояния экрана

| Состояние | Условие |
|---|---|
| default | сводка-метрики + таблица пользователей |
| empty (поиск) | по запросу `?q` ничего не найдено → «Ничего не найдено» |
| empty (нет данных) | пользователей нет вовсе → «Пользователей нет» |
| 404 | заход не-админа (вместо экрана — страница «не найдено») |

> Отдельных loading/error-состояний в UI нет — экран рендерится на сервере целиком
> (это нормально для read-only админки v1).

## Элементы интерфейса

### Заголовок «Пользователи» + ссылка «На главную»
- **Ссылка «На главную»:** → `/`

### Мини-сводка (3 карточки-метрики)
- **Видима:** всегда · **Показывает:** «Пользователей», «Досок», «Новых за 7 дней» (числа из БД)

### Поиск
- **Поле** `type=search`, имя параметра `q`; **кнопка «Искать»** (форма `method=get`)
- **При действии:** перезагрузка с `?q=…`; фильтр по имени ИЛИ email

### Таблица пользователей
- **Колонки:** Имя (ссылка → детали), Email, Регистрация (дата), Проекты (число)
- **Строка:** клик по имени → [Детали пользователя](admin-user-details.md) (`/admin/users/[id]`)
- **Пусто:** сообщение под таблицей («Ничего не найдено» / «Пользователей нет»)

## Сообщения

| Ситуация | Тип | Текст сообщения |
|---|---|---|
| Поиск без результатов | info | «Ничего не найдено» |
| Пользователей нет | info | «Пользователей нет» |
| Заход не-админа | — | страница 404 |

## Открытые вопросы / находки
- **Read-only v1.** В коде НЕТ (хотя в старой спеке были «целевыми»): колонки роль/статус,
  быстрые действия (сменить роль, заблокировать), фильтр по роли/статусу, пагинация.
  Роль в БД (`User.role`) + действия — после Урока 7 (отмечено в backlog).
- **Доступ через 404, не редирект.** Не-админ получает `notFound()` (404), а не редирект на `/login` —
  это осознанно (скрываем существование админки).
