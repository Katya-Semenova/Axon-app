# Экран: Список пользователей (`/admin/users`) — *Admin · v1 read-only*

> **v1 (Урок 5, Шаг 2):** гейт по `ADMIN_EMAIL`, read-only. Реализовано: сводка-метрики +
> список (имя/email/дата/число проектов) + поиск. НЕ в v1 (после Урока 7): колонки роль/статус,
> смена роли, блок, пагинация, DataTable-organism. Ниже — полное (целевое) видение.

**Доступ:** только **Admin** (v1 — по `ADMIN_EMAIL`). Не-admin (гость/пользователь) на `/admin/*` → редирект на [404](404.md) (скрываем существование админки).

## Layout
Таблица аккаунтов + поиск/фильтр/сортировка сверху.

## Данные
Все аккаунты — из бэкенда. Колонки: имя, email, роль, статус (активен/заблокирован), дата регистрации, число проектов.

## Состояния
- **default:** таблица.
- **empty:** «Пользователей нет» (маловероятно).
- **loading:** скелетон таблицы.
- **error:** «Не удалось загрузить» + повтор.
- Поиск без результатов — «Ничего не найдено».

## Действия
- Поиск по имени/email; фильтр по роли/статусу; сортировка по колонкам.
- Клик по строке → [Детали пользователя](admin-user-details.md).
- Быстрые действия в строке: сменить роль, заблокировать/разблокировать (с подтверждением).
- Массовые действия — в v1 не делаем (позже).

## Связи
Доступен из меню аватара только для Admin. → [Детали пользователя](admin-user-details.md).

## Визуал

### Layout Desktop
- Контейнер full-width с боковыми отступами; сверху — панель поиска/фильтра; ниже — таблица аккаунтов.

### Layout Mobile (≤640px)
- Таблица → карточки-строки (стек); фильтры в `<DropdownMenu>`. **TODO:** мобильный layout таблицы.

### Компоненты (сверху вниз)
- **Поиск** → `<Input inputSize="sm">` (с иконкой); **фильтры** роль/статус → `<DropdownMenu>` или чипы `<Chip>`/`<Badge>`.
- **Таблица** — колонки имя/email/роль/статус/дата/проекты. **TODO:** `Table`/`DataTable` (organism) в ките нет — добавить (универсальная: columns+data, сортировка, пагинация).
- Статус ячейки → `<Badge>` (success «активен» / error «заблокирован»); роль → `<Badge variant="outline">`.
- Действия в строке (сменить роль / блок) → `<DropdownMenu>` + `<AlertDialog>` подтверждение.
- **Пагинация** — **TODO:** компонент `Pagination`.

### Визуальные состояния
- **default:** таблица. **loading:** `<Skeleton>` строк. **empty:** «Пользователей нет». **error:** «Не удалось загрузить» + `<Button>` повтор. Поиск без результатов: «Ничего не найдено».

### Edge cases визуально
- Много аккаунтов → пагинация/виртуализация; длинный email → truncate.
