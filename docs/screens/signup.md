# Экран: Регистрация (`/signup`) — *нужен, нет в коде*

**Доступ:** гость. Авторизованного — редирект.

## Layout
Форма: имя, email, пароль (+ подтверждение пароля), чекбокс согласия с условиями. Кнопка «Создать аккаунт». Ссылка «Уже есть аккаунт? Войти».

## Данные
Создание аккаунта через бэкенд. Роль по умолчанию — **Пользователь**.

## Состояния
- **default:** форма.
- **loading:** submit.
- **error:** занятый email → «Этот email уже зарегистрирован»; слабый/несовпадающий пароль → подсказка.
- **success:** аккаунт создан → вход в продукт; показываем [Onboarding](onboarding.md).

## Валидация
- имя — не пусто.
- email — формат + уникальность (проверка на бэкенде).
- пароль — мин. длина (напр. 8), совпадение с подтверждением.
- согласие — обязательный чекбокс.

## Действия
- «Создать аккаунт» → success/ошибка.
- «Войти» → [Вход](login.md).
- Если регистрация началась из гостевого воркспейса — после входа **переносим текущий проект** в аккаунт.

## Связи
Из [Вход](login.md), из меню аватара, из гейта «Сохранить проект».

## Визуал

### Layout Desktop
- Карточка формы по центру (`<Card>` ~360px), wordmark «AXON» сверху.
- Поля: имя → email → пароль → подтверждение пароля → чекбокс согласия → `<Button>` «Создать аккаунт» → ссылка «Уже есть аккаунт? Войти».

### Layout Mobile (≤640px)
- Full-width форма, padding 16px, tap-таргеты ≥44px.

### Компоненты (сверху вниз)
- `<FormField>` × имя/email/пароль/подтверждение → `<Input>` (invalid при ошибке).
- Чекбокс согласия с условиями. **TODO:** `Checkbox` (atom) в ките нет — добавить.
- `<Button variant="primary" size="lg" className="w-full">` «Создать аккаунт» (`loading`).
- «Войти» → `<Button variant="link">`.

### Визуальные состояния
- **default** / **loading** / **error:** занятый email → `invalid` + «Этот email уже зарегистрирован»; несовпадение паролей → оба `invalid` + подсказка. **success:** → [Onboarding](onboarding.md).

### Edge cases визуально
- Слабый пароль — подсказка под полем; согласие не отмечено — кнопка disabled.
