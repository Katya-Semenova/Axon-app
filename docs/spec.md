# Spec продукта Axon

## Продукт

- **Что:** Инструмент, который превращает сырые данные в готовую презентацию. Пользователь загружает файл → получает «editorial insight-карточки» на холсте → собирает из них слайды → презентует. Слоган продукта: «Your data, in plain English».
- **Проблема, которую решаем:** Превратить сырые данные во внятную презентацию — долго и вручную: надо разобрать данные, понять, что в них важно, и упаковать всё в красивые слайды. Между «есть файл» и «есть что показать» — часы работы.
- **Ключевая ценность:** Загрузил файл — и ИИ сам быстро достаёт из него инсайты и собирает из них готовые дата-сеты (графики) — это готовый первый срез данных. Пользователь при желании правит его сам: переносит инсайты между дата-сетами (отсоединяет/присоединяет ноды), открывает и редактирует сами дата-сеты, — а затем складывает из нужных слайды и красиво оформляет презентацию. Весь путь от файла до показа проходит **очень быстро**. Суть: ИИ даёт готовое, а пользователь меняет под себя. Отдельно ценится «редакторский», журнальный вид (в отличие от сухих дашбордов).
- **Для кого:** Те, кому нужно быстро превратить данные в наглядный показ:
  - Основатели / руководители — быстро понять данные и показать инвесторам/команде.
  - Аналитики данных — ускорить превращение выгрузок в визуальные инсайты и отчёты.
  - Консультанты / агентства — готовить отчёты и презентации клиентам, ценят скорость и вид.
  - Product / маркетинг — регулярно показывать метрики и результаты экспериментов.
- **Главная задача (главный сценарий):** Загрузить файл → ИИ извлекает инсайты и собирает из них готовые дата-сеты (узлы на холсте) → пользователь при желании правит (переносит инсайты, редактирует дата-сеты) и выбирает нужные → собирает слайды → выгрузить/показать презентацию.
- **Основные действия в продукте:**
  - Загрузка файла на главной приложения (dropzone или клик) → создаётся проект; **ИИ** извлекает Insight-карточки и собирает из них готовые DataSet-узлы (первый срез).
  - **Добавить ещё файл** можно прямо на холсте — кнопка «+ Добавить файл» в чат-рейле: его инсайты/дата-сеты/слайды **дописываются** к текущей доске (не заменяя её), узлы кладутся ниже текущих. Гость — в памяти, вошедший — автосейв. Та же инфраструктура позже переиспользуется живым ИИ-чатом (Шаг 11).
  - **Data mode (холст)** — node-граф: Insight-карточки (данные / текст / SQL / код) → связи (Connection) → DataSet-карточки (агрегирующий график), построенные ИИ. Пользователь может **отсоединять/переподключать** инсайты к другим дата-сетам и **редактировать** дата-сеты. Сбоку AI-чат-рейл (живой чат — позже на GigaChat; пока в нём список загруженных файлов и кнопка «+ Добавить файл», заглушка-ввод обезврежена — Шаг 11); drill-in вью для Insight и DataSet.
  - **Presentation mode (СЛАЙДЫ)** — слайды из дата-сетов. Центр — слайд (только inline-текст); правый рельс из двух секций по скоупу: «ЭТОТ СЛАЙД» (один плоский дропдаун **«Как показать этот слайд»** — смысл крупно + техн. термин серым, без слов-категорий) и «ВСЯ ПРЕЗЕНТАЦИЯ» (Тема + Заметки); снизу — лента слайдов с сортировкой + «+ Слайд». Стиль = одна ось **Тема** (пресеты, deck-wide; Web-dashboard свет/тьма). Вид (archetype) + тип графика ставит ИИ, пользователь правит как override. *(Рерайт Slides — см. `screens/slides.md`; движок рендера графиков — см. пункт «Движок рендера» ниже.)*
  - **Build mode (ПОКАЗ)** — чистый вывод презентации: формат (ссылка / PDF / PPTX / Web-dashboard (Interactive) — переименована из «Interactive · Live dashboard» 05.07, единая линия с темой Web-dashboard в Слайдах; **работает с 05.07**: выдаёт ту же публичную ссылку с `?view=dashboard` — таб-дашборд, см. ниже) + перестановка + показ (Present). *(Audience/Tone убраны из режима СЛАЙДЫ (Шаг 3); в BuildMode пока работают — полная очистка ПОКАЗ от чат-сборки под аудиторию/тон — отдельным шагом на экране Present.)*
  - Дашборд «Recent Projects» — список недавних проектов со статусами (ready / draft / generating).
  - Storybook — витрина дизайн-системы (токены и компоненты).
- **Поддерживаемые типы графиков (10 активных):** Treemap, Heatmap, Map, Lollipop, Donut, Stacked Bar, Dot Matrix, Scatter, Radar, Spline Area.
- **Движок рендера графиков (2026-07-05):** по умолчанию — родной SVG-рендерер AXON (`native`,
  `ChartRenderer.tsx`). Вторым движком подключён **Highcharts** — строго ЗА ФЛАГОМ
  `RENDER_ENGINE` в `lib/renderEngine.ts` (сейчас `"native"`, включается сменой одной строки;
  на прод — только после презентации ~11.07). Покрытые Highcharts типы — список
  `HIGHCHARTS_TYPES` там же (бары со спайка + волна 1: Heatmap, Lollipop, Scatter, Radar,
  Donut, Line/Area/Spline Area); новый тип = запись в список + кейс в `HighchartsRenderer.tsx`.
  Цвета/шрифты Highcharts берёт из токенов темы `--slide-*` (мост через getComputedStyle,
  без хардкода хексов); рендерер живёт только на клиенте (`next/dynamic ssr:false`).
  Родной путь при флаге `native` не затронут. Волна 2 (Treemap, Dot Matrix, Map) — в backlog 🎯.
- **Разведение типов при авто-подборе (2026-07-04):** соседние по порядку дата-сеты/слайды не получают
  один и тот же тип графика, если у их формы данных есть совместимая альтернатива (ранжирование
  совместимых типов — `chart-rules.ts → rankChartTypes`). Работает в обоих путях: в движке правил и
  поверх ИИ-плана (подмена только ВНУТРИ совместимого ранга — строки/числа не меняются, меняется вид);
  ИИ дополнительно просят чередовать типы в промпте. Если альтернативы нет (напр., матрица чисел →
  Heatmap, длинный временной ряд → Spline Area) — повтор допустим. Ручной выбор пользователя не трогается.
- **Запасные тексты слайдов — на языке ДАННЫХ (2026-07-04):** когда у слайда нет ИИ-нарратива,
  показываются честная сводка из реальных чисел (`deriveSlideSummary`) и речь докладчика — обе
  строятся на языке данных (кириллица в метках/колонках → русский, иначе английский), как и
  служебная «Сводка по файлу» (EC-2). Выдуманные заглушки Audience×Tone (фиктивный текст про
  «Q3 −18%», не связанный с данными) СНЯТЫ — запасной текст не может противоречить данным.
- **Что НЕ делаем в первой версии (out of scope):** реальный разбор PDF / картинок / SQL в инсайты (в v1 принимаем, но инсайты по ним упрощённые — см. EC-1 и «Объём v1»); командная работа в реальном времени.

### Объём v1 — что реально работает (решение от 2026-06-13)
Цель v1 — **рабочий сквозной демо** (вход под аккаунтом → загрузка файла → инсайты → слайды → презентация → шаринг), а не только кликабельная витрина.
- **Аккаунты и хранение — по-настоящему:** регистрация/вход, роли (Гость / Пользователь / Admin), сохранение проектов, история версий, шаринг по ссылке — реальные (бэкенд/API).
- **CSV / Excel — реальный разбор:** ✅ **реализовано (Шаг 10):** файл пользователя действительно парсится в строки/колонки и рисуется на графиках (инсайты из *его* данных). Конвейер: `lib/file-parsing` (CSV — papaparse, .xlsx — read-excel-file) → `lib/insight-engine` (`ParsedTable → BoardData`, правила без ИИ: типы колонок → выбор графика → инсайты/дата-сеты/слайды). Холст грузит результат через `store.hydrate` (гость — в памяти) либо `createProjectFromData` (вошедший — автосейв в свой проект). Граница `ParsedTable → BoardData` — сменный разъём под ИИ (в Уроке 5, Шаг 1 в него встаёт реальный ИИ-разбор; правила становятся **fallback** — см. ниже «ИИ в продукте»). Ограничения v1: CSV читаем как UTF-8 (Windows-1251 пока не детектируем), старый .xls и .ods не поддержаны, текстовое резюме EC-2 — только RU.
- **PDF / картинки / SQL — принимаем (обещание «любой файл», EC-1), но инсайты упрощённые** + бейдж «Beta» и плашка-объяснение. Полный разбор этих форматов — после v1 (roadmap, сообщаем пользователю в UI).
- **ИИ в продукте — провайдер-агностичный слой (решено Урок 5, Шаг 1; см. [ADR-008](decisions/ADR-008-ai-provider.md)):** ИИ подключается через сменный слой `lib/ai/` с адаптерами — смена провайдера = смена конфига, не переписывание. **Дефолт для MVP-демо — OpenRouter** (доступ к актуальным моделям Claude/GPT — лучшая «импрессия» на показе). **GigaChat (Сбер) — поддерживаемая опция** (адаптер-заготовка): официальный API, оплата в рублях, работает в РФ — для РФ-аудитории на проде. Финальный выбор OpenRouter↔GigaChat отложен осознанно (агностичность это позволяет). Ключи — **только сервер** (`.env*`), вызовы из `/api/ai/*`. **Нюанс РФ:** Claude/OpenAI напрямую в РФ — геоблок + нельзя оплатить, поэтому на проде для РФ-аудитории остаётся GigaChat.
  - **(а) Извлечение инсайтов реальным ИИ — ✅ Урок 5, Шаг 1 (код готов; живой путь включается ключом `OPENROUTER_API_KEY`):** ИИ встаёт в разъём `ParsedTable → BoardData` (`lib/ai/` + `lib/insight-engine/ai-plan.ts` + route `/api/ai/extract`; проводка в `LandingPage`/`ChatRail` через `lib/insight-engine/extract.ts`). **Гибрид:** ИИ формирует состав дата-сетов, выбирает тип графика (из 10) и пишет заголовок + **нарратив-инсайт словами** (plain English; нарратив протекает в слайд) — а **фактические числа строк считает код** из реальных данных (защита от галлюцинации цифр). Приватность: провайдеру уходит только **схема колонок + выборка строк**, полная таблица остаётся в браузере. Доступ — **только вошедшим** (лимит/расход), гость получает разбор по правилам. Синхронно (спиннер; EC-3 = loading). Сбой ИИ / нет ключа / таймаут / невалидный ответ → **fallback на правила**.
  - **(б) Живой AI-чат по данным — ✅ Урок 5, Шаг 1 (код готов; живой путь — ключ `OPENROUTER_API_KEY`):** в чат-рейле Data-режима ИИ **отвечает словами** по разобранной доске (контекст = сводка инсайтов/дата-сетов, не сырой файл; только вошедшим; ответ целиком, без стрима). **Советник + «Построить новый инсайт»:** когда уместно, ИИ предлагает достроить новый инсайт-график из данных пользователя → кнопка **«Применить»** (human-in-the-loop: ИИ сам холст не меняет, строит по клику, числа — реальные, через `executePlan`). Правки существующего (тип графика/удаление/строки) — НЕ через чат: это пользователь делает руками (дропдаун/drill-in). Для построения стор держит последнюю `ParsedTable` в памяти (не персист). Сбой ИИ → ошибка в чате (rules-fallback тут невозможен). Лог чата хранится **в документе доски `BoardData`** (ADR-003), не отдельной таблицей в v1.

### Авторизация и роли — решено (Шаг 4)
- Целевое: **аккаунты + роли Гость / Пользователь / Admin** (детали — раздел «Доступы и роли» ниже).
- **Реализовано (Урок 4, Шаг 5):** вход/регистрация по **email+паролю** через **Better Auth** (см. [ADR-004](decisions/ADR-004-auth-library.md)). Пароли — хеш (scrypt), не открытым текстом. Таблицы `Session/Account/Verification`. Шапка показывает состояние входа (`AuthNav`: «Войти» / аватар + «Выйти»). Роль **Admin** — позже (Урок 5).
- **Письма аккаунта (Урок 4, Шаг 6):** через **Resend + React Email** (см. [ADR-005](decisions/ADR-005-email-provider.md)). Сделаны: **сброс пароля** (экраны `/forgot-password` → `/reset-password?token=`), уведомление **«пароль изменён»**, **welcome** при регистрации. Письма двуязычные (RU/EN по локали пользователя), отправитель `Axon <noreply@axon-app.ru>`. `/forgot-password` отвечает нейтрально — не раскрывает, есть ли аккаунт. Шаблоны — в `emails/`, отправка — `lib/email.ts`, превью — `npm run email:dev`.
- **Подтверждение email (verify-email) — отложено (после Урока 5).** Сейчас `requireEmailVerification: false`; включение = переключатель + один шаблон verify-email. Решение: меньше трения для первых пользователей/демо.

### Edge cases

**EC-1. Файл нельзя разобрать или превышен лимит объёма**
Принимаем **любой** тип файла (pdf, excel, csv, sql, txt, json, svg, png/jpg, скриншот — без белого списка). Два уровня разбора (см. «Объём v1»):
- **CSV / Excel** — полный разбор: инсайты считаются из данных пользователя.
- **PDF / картинки / SQL / прочее** — принимаем, но инсайты **упрощённые**: показываем плашку «Это предварительные инсайты — полный разбор PDF/картинок скоро, для точных результатов загрузите CSV/Excel» + бейдж **Beta** на карточках.

Понятную ошибку показываем **только** если разобрать не вышло (битый / запароленный / пустой файл) или превышен лимит объёма: рамка dropzone краснеет, показывает причину («файл повреждён» / «файл > 50 МБ») и предлагает снова.
> ✅ **Сделано (Шаг 10):** копирайт дропзоны переписан на два уровня: «**CSV, Excel** — полный разбор · **PDF, картинки, SQL** — в бете» (двуязычно, ключи `Landing.dropzone`). Ошибки разбора (EC-1) показываем красной рамкой dropzone с причиной (превышен размер / пусто / битый / не та колонка / формат в бете). Финальные формулировки — Урок 7. Beta-путь для PDF/картинок/SQL пока открывает демо-холст (упрощённые инсайты по ним — отдельный будущий шаг).

**EC-2. Файл разобран, но инсайтов не извлечено (пусто)**
Пустой холст + чат-подсказка: «опиши в чате, что хочешь увидеть» / «добавить инсайт вручную». Пользователь не в тупике, есть путь дальше.

**EC-3. Обработка файла занимает время (статус «generating»)**
Карточка проекта показывает статус «generating», на холсте — скелетоны карточек. Не блокирует: можно уйти и вернуться.

**EC-4. Доступ без аккаунта (гость)**
Гость может загрузить файл и поиграться без регистрации. Чтобы сохранить проект и вернуться к нему — нужен вход/регистрация. (Согласуется с целевым «аккаунты + роли».)

## Платформа
- **Тип:** web, responsive (desktop-first, аудитория работает с данными за компьютером).
- **PWA — НЕ делаем (решение 2026-06-21, Урок 6 Шаг 4 пропущен):** AXON — десктоп-инструмент, разбор
  синхронный (пушить нечего). Минимальный PWA (иконка+манифест) — опционально позже, см. `backlog.md`.
- **URL приложения (Урок 6, Задание 1.1, [ADR-010](decisions/ADR-010-app-url.md)):** лендинг — на
  корне `/` (axon-app.ru), сервис — на подстранице **`/ai-studio`** того же домена (не поддомен). Один
  origin → cookie входа и cookie языка общие для лендинга и сервиса. Поддомен `app.axon-app.ru`
  отложен до роста проекта. От этого решения зависят индексация, редиректы и `start_url` PWA.
  - **Реализация (2026-06-22):** через Next.js `basePath: "/ai-studio"` у сервиса (`apps/app`).
    Слово приставки выбрано `ai-studio` (не `app`): домен уже содержит «app» → `/app` читался бы
    «app дважды»; «ai-studio» не дублирует и выводит вперёд ИИ-помощник + образ «студии/авторства».
    nginx делит просто: `/` → лендинг, `/ai-studio` → сервис (вся раздача сервиса ушла под префикс).

## Мультиязычность (i18n) — решено 2026-06-14
Интерфейс приложения доступен на нескольких языках с переключением.
- **Языки на старте:** Русский + Английский. **Архитектура — на рост:** добавление нового языка = новый файл-словарь, без переделки кода.
- **Язык по умолчанию:** автоопределение по языку браузера (заголовок `Accept-Language`) при первом заходе. Явный выбор пользователя запоминается в cookie и имеет приоритет. Fallback — **английский** (если язык браузера не ru/en). _(Решение 2026-06-14: автоопределение, чтобы русскоязычный видел русский, остальной мир — английскую «красивую импрессию»; раньше был жёсткий дефолт RU.)_
- **Что переводим:** интерфейс — кнопки, меню, подписи, состояния (loading/empty/error), тексты экранов, письма аккаунта (когда появятся).
- **Что НЕ переводим:** пользовательский контент (загруженные данные, названия проектов, инсайты) и ответы ИИ — они на языке данных/пользователя. Это отдельная история, не часть UI-перевода.
- **Переключатель языка:** компонент в интерфейсе (через дизайн-систему/UI-кит, не инлайн); выбор запоминается между сессиями.
- **Подход внедрения:** «фундамент-первый» — сначала ставим i18n-каркас и переводим существующие экраны, далее **новые экраны (Урок 4: login/settings/notifications) строятся сразу двуязычными** (без двойной работы). i18n — код приложения, от хостинга (переезд на VPS, [ADR-002](decisions/ADR-002-hosting-migration.md)) не зависит.
- **Реализовано:** `next-intl` v4, локаль **через cookie** (без URL-префикса), дефолт — автоопределение по `Accept-Language`. Каркас + переключатель RU/EN, весь видимый UI переведён (15 namespace-словарей).

## Доступы и роли

Аккаунты + роли. Вход/регистрация (email+пароль, Better Auth) **реализованы** в Уроке 4, Шаг 5. **Admin v1 (Урок 5, Шаг 2): доступ по `ADMIN_EMAIL` (env), read-only; роль в БД (`User.role`) — после Урока 7.**

| Роль | Кто это | Что доступно |
|---|---|---|
| **Гость** | не авторизован | Главная приложения, Storybook, загрузить файл и поработать в воркспейсе (canvas/slides/build). **Нельзя без входа:** сохранить проект и вернуться к нему, шарить по ссылке, экспортировать. |
| **Пользователь** | вошёл в аккаунт | всё гостевое + сохранение проектов, «Recent Projects» свои, история/автосейв, шаринг по ссылке, Профиль, Настройки. |
| **Admin / владелец** | `ADMIN_EMAIL` (v1; роль в БД — после Урока 7) | всё пользовательское + Админка **read-only**: сводка-метрики, список пользователей, детали + их доски. Управление ролями / блокировка / удаление — позже. |

**Момент «требуем вход» (EC-4):** гость работает свободно; вход требуется на действиях **«Сохранить проект»**, **«Поделиться»**, **«Экспорт»** и при попытке **использовать ИИ-чат** (ИИ — только вошедшим: расход/приватность). На этих действиях гостю показываем форму входа/регистрации, после чего текущий проект переносится в аккаунт; в случае ИИ-чата холст не теряется и чат просто разблокируется.

> **Статус реализации (Шаг 7):** доски **разведены по пользователям**. Вошедший видит свой список **«Мои проекты»** (на дашборде `/`): создать / открыть / переименовать / удалить; новый проект наполняется демо-сидом. Авто-сохранение пишет в **конкретную доску владельца** (`BoardSync` привязан к `boardId`). Серверные `getBoard / saveBoard / listProjects / createProject / deleteProject / renameProject` берут владельца **только из серверной сессии** и проверяют `Board.ownerId === userId` (**IDOR-защита** — долг Шага 5 закрыт; чужая/несуществующая доска → «не найдено»). Гость работает с холстом в памяти, в БД не пишет. **Перенос гостевого проекта в аккаунт (Шаг 7b — сделано):** в воркспейсе у гостя есть кнопка **«Сохранить»** → инлайн-окно входа/регистрации (`AuthModal`) → после входа текущий холст сохраняется в **новый проект** аккаунта (`createProjectFromData`), воркспейс привязывается к этой доске (дальше автосейв), тост «Проект сохранён». Тот же `AuthModal` открывается, когда гость кликает по полю **ИИ-чата** (ИИ закрыт гостю): после входа холст остаётся на месте, чат разблокируется (отдельного сохранения не требуется). **Поделиться по ссылке (Шаг 12 — сделано):** в «Показе» владелец создаёт публичную ссылку `/p/[token]` (модель `ShareLink`); получатель открывает read-only деку **без входа**; владелец может **отозвать**. Гость → вход + сохранение, затем ссылка. Создание/отзыв — только владелец из серверной сессии (IDOR). **Веб-дашборд (Interactive, 05.07):** формат «Web-dashboard (Interactive)» в Показе выдаёт ТУ ЖЕ публичную ссылку с параметром `?view=dashboard` — дека открывается таб-дашбордом: сверху закладки по слайдам (название дата-сета или «Слайд N»), один слайд на экране, переключение кликом, без скролла и переходов; токен общий с обычной ссылкой (отзыв гасит обе). Табы стилизуются токенами `--slide-*` выбранной темы. **Экспорт PPTX/PDF — в бэклоге** (другой механизм — генерация файла, см. [ADR-007](decisions/ADR-007-sharing.md)).
