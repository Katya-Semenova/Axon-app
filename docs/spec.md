# Spec продукта Axon

## Продукт

- **Что:** Инструмент, который превращает сырые данные в готовую презентацию. Пользователь загружает файл → получает «editorial insight-карточки» на холсте → собирает из них слайды → презентует. Слоган продукта: «Your data, in plain English».
- **Проблема, которую решаем:** Превратить сырые данные во внятную презентацию — долго и вручную: надо разобрать данные, понять, что в них важно, и упаковать всё в красивые слайды. Между «есть файл» и «есть что показать» — часы работы.
- **Ключевая ценность:** Загрузил файл — и ИИ сам быстро достаёт из него инсайты и собирает из них готовые дата-сеты (графики) — это готовый первый срез данных. Пользователь при желании правит его сам: переносит инсайты между дата-сетами (отсоединяет/присоединяет ноды), открывает и редактирует сами дата-сеты, — а затем складывает из нужных слайды и красиво оформляет презентацию. Весь путь от файла до показа проходит **очень быстро**. Суть: ИИ даёт готовое, а пользователь меняет под себя. Отдельно ценится «редакторский», журнальный вид (в отличие от сухих дашбордов).
- **Для кого:** Те, кому нужно быстро превратить данные в наглядный показ:
  - Основатели / руководители — быстро понять данные и показать инвесторам/команде.
  - Аналитики данных — ускорить превращение выгрузок в визуальные инсайты и отчёты.
  - Консультанты / агентства — готовить отчёты и презентации клиентам, ценят скорость и вид.
  - Product / маркетинг — регулярно показывать метрики и результаты экспериментов.
- **Главная задача (главный сценарий):** Загрузить файл → ИИ извлекает инсайты и собирает из них готовые дата-сеты (узлы на холсте) → пользователь при желании правит (переносит инсайты, редактирует дата-сеты) и выбирает нужные → собирает слайды → выгрузить/показать презентацию.
- **Основные действия в продукте:**
  - Загрузка файла на главной приложения (dropzone или клик) → создаётся проект; **ИИ** извлекает Insight-карточки и собирает из них готовые DataSet-узлы (первый срез).
  - **Data mode (холст)** — node-граф: Insight-карточки (данные / текст / SQL / код) → связи (Connection) → DataSet-карточки (агрегирующий график), построенные ИИ. Пользователь может **отсоединять/переподключать** инсайты к другим дата-сетам и **редактировать** дата-сеты. Сбоку живой AI-чат-рейл; drill-in вью для Insight и DataSet.
  - **Presentation mode** — слайды из дата-сетов: архетипы (Chart, Big Number, Comparison, Sentiment, Word List, Quote), лоток слайдов с сортировкой, темы (Editorial / Soft), движки рендера (SciChart / Highcharts / D3).
  - **Build mode** — чат-сборка деки под аудиторию (CEO / Board / Team / Investor / Custom) и тон (Formal / Neutral / Casual); экспорт и режим показа (Present).
  - Дашборд «Recent Projects» — список недавних проектов со статусами (ready / draft / generating).
  - Storybook — витрина дизайн-системы (токены и компоненты).
- **Поддерживаемые типы графиков (10 активных):** Treemap, Heatmap, Map, Lollipop, Donut, Stacked Bar, Dot Matrix, Scatter, Radar, Spline Area.
- **Что НЕ делаем в первой версии (out of scope):** реальный разбор PDF / картинок / SQL в инсайты (в v1 принимаем, но инсайты по ним упрощённые — см. EC-1 и «Объём v1»); командная работа в реальном времени.

### Объём v1 — что реально работает (решение от 2026-06-13)
Цель v1 — **рабочий сквозной демо** (вход под аккаунтом → загрузка файла → инсайты → слайды → презентация → шаринг), а не только кликабельная витрина.
- **Аккаунты и хранение — по-настоящему:** регистрация/вход, роли (Гость / Пользователь / Admin), сохранение проектов, история версий, шаринг по ссылке — реальные (бэкенд/API).
- **CSV / Excel — реальный разбор:** файл пользователя действительно парсится в строки/колонки и рисуется на графиках (инсайты из *его* данных).
- **PDF / картинки / SQL — принимаем (обещание «любой файл», EC-1), но инсайты упрощённые** + бейдж «Beta» и плашка-объяснение. Полный разбор этих форматов — после v1 (roadmap, сообщаем пользователю в UI).
- **AI-чат — живой, на российском провайдере [GigaChat (Сбер)]:** официальный API, оплата в рублях, работает в РФ. Чат отвечает по разобранным данным пользователя (CSV/Excel) и помогает с инсайтами/декой. **Почему не Claude/OpenAI:** геоблок и оплата в РФ — для аудитории из России недоступны (тот же класс ограничения, что у провайдера аватаров). Интеграция стандартная: API-ключ → запрос (вопрос + контекст данных) → ответ. Оплата по запросу (копейки), есть бесплатный тариф для старта.

### Авторизация и роли — решено (Шаг 4)
- Целевое: **аккаунты + роли Гость / Пользователь / Admin** (детали — раздел «Доступы и роли» ниже). Текущий код — прототип без авторизации (статичный аватар «KS», Projects/Docs — заглушки); в v1 заменяется реальными аккаунтами/бэкендом.

### Edge cases

**EC-1. Файл нельзя разобрать или превышен лимит объёма**
Принимаем **любой** тип файла (pdf, excel, csv, sql, txt, json, svg, png/jpg, скриншот — без белого списка). Два уровня разбора (см. «Объём v1»):
- **CSV / Excel** — полный разбор: инсайты считаются из данных пользователя.
- **PDF / картинки / SQL / прочее** — принимаем, но инсайты **упрощённые**: показываем плашку «Это предварительные инсайты — полный разбор PDF/картинок скоро, для точных результатов загрузите CSV/Excel» + бейдж **Beta** на карточках.

Понятную ошибку показываем **только** если разобрать не вышло (битый / запароленный / пустой файл) или превышен лимит объёма: рамка dropzone краснеет, показывает причину («файл повреждён» / «файл > 50 МБ») и предлагает снова.
> Копирайт дропзоны переписываем на два уровня: «**CSV, Excel** — полный разбор · **PDF, картинки, SQL** — принимаем, разбор в бете». Текущий код пишет ровный белый список — поправить в Уроке 2+ (сначала спека — здесь — потом код, финальные формулировки — Урок 7).

**EC-2. Файл разобран, но инсайтов не извлечено (пусто)**
Пустой холст + чат-подсказка: «опиши в чате, что хочешь увидеть» / «добавить инсайт вручную». Пользователь не в тупике, есть путь дальше.

**EC-3. Обработка файла занимает время (статус «generating»)**
Карточка проекта показывает статус «generating», на холсте — скелетоны карточек. Не блокирует: можно уйти и вернуться.

**EC-4. Доступ без аккаунта (гость)**
Гость может загрузить файл и поиграться без регистрации. Чтобы сохранить проект и вернуться к нему — нужен вход/регистрация. (Согласуется с целевым «аккаунты + роли».)

*Выбран путь работы с дизайном: Б — свой дизайн / готовый код и задеплоенный прототип.*

## Платформа
- **Тип:** web, responsive (desktop-first, аудитория работает с данными за компьютером).

## Мультиязычность (i18n) — решено 2026-06-14
Интерфейс приложения доступен на нескольких языках с переключением.
- **Языки на старте:** Русский + Английский. **Архитектура — на рост:** добавление нового языка = новый файл-словарь, без переделки кода.
- **Язык по умолчанию:** Русский (аудитория в основном из РФ), с переключением на английский.
- **Что переводим:** интерфейс — кнопки, меню, подписи, состояния (loading/empty/error), тексты экранов, письма аккаунта (когда появятся).
- **Что НЕ переводим:** пользовательский контент (загруженные данные, названия проектов, инсайты) и ответы ИИ — они на языке данных/пользователя. Это отдельная история, не часть UI-перевода.
- **Переключатель языка:** компонент в интерфейсе (через дизайн-систему/UI-кит, не инлайн); выбор запоминается между сессиями.
- **Подход внедрения:** «фундамент-первый» — сначала ставим i18n-каркас и переводим существующие экраны, далее **новые экраны (Урок 4: login/settings/notifications) строятся сразу двуязычными** (без двойной работы). i18n — код приложения, от хостинга (переезд на VPS, [ADR-002](decisions/ADR-002-hosting-migration.md)) не зависит.
- **Библиотека (план):** `next-intl` (стандарт для Next.js App Router). Точный механизм локали (URL-префикс `/ru`,`/en` vs cookie) финализируем на реализации; склоняемся к простому варианту с заделом на рост.
- **Дизайн-нюанс:** RU-текст длиннее EN → вёрстка «Editorial Density» должна выдерживать длинные строки (проверять при переводе).

## Стек (из кода)
- Frontend: Next.js (App Router, директория `app/` в корне — НЕ `src/`)
- Язык: TypeScript
- Стили: Tailwind CSS
- Состояние: Zustand (`lib/store.ts`)
- Графики: d3-hierarchy (treemap squarify) + собственные рендереры (`app/components/ChartRenderer.tsx`, `MiniChart.tsx`)
- Данные: мок-данные (`lib/mockData.ts`) — реального бэкенда пока нет
- Модель данных: `lib/types.ts`

### Модель данных (иерархия сущностей)
`Insight` (3-й уровень: data / text / sql / code) → `Connection` → `DataSet` (2-й уровень: агрегирующий график) → `Slide` (1-й уровень: единица презентации).

## Доступы и роли

Целевое состояние — аккаунты + роли (текущий код — прототип без авторизации, статичный аватар «KS»).

| Роль | Кто это | Что доступно |
|---|---|---|
| **Гость** | не авторизован | Главная приложения, Storybook, загрузить файл и поработать в воркспейсе (canvas/slides/build). **Нельзя без входа:** сохранить проект и вернуться к нему, шарить по ссылке, экспортировать. |
| **Пользователь** | вошёл в аккаунт | всё гостевое + сохранение проектов, «Recent Projects» свои, история/автосейв, шаринг по ссылке, Профиль, Настройки. |
| **Admin** | сотрудник | всё пользовательское + Админка: список пользователей, детали пользователя, управление ролями/блокировкой. |

**Момент «требуем вход» (EC-4):** гость работает свободно; вход требуется на действиях **«Сохранить проект»**, **«Поделиться»** и **«Экспорт»**. На этих действиях гостю показываем форму входа/регистрации, после чего текущий проект переносится в аккаунт.

## Данные (модель)

Целевая модель для бэкенда v1 (текущий код — мок `lib/mockData.ts` + `lib/types.ts`; иерархия Insight → Connection → DataSet → Slide сохраняется).

### User
- id, name, email, passwordHash, role (`guest` | `user` | `admin`), status (`active` | `blocked`), createdAt, onboardingDone

### Project
- id, ownerId (→ User), title, status (`ready` | `draft` | `generating`), createdAt, updatedAt
- sourceFiles[] (имя, тип, размер, уровень разбора: `full` для CSV/Excel / `beta` для PDF/картинок/SQL)

### Insight  *(3-й уровень)*
- id, projectId, kind (`data` | `text` | `sql` | `code`), title, data (rows/columns/chartType) | text, isBeta, position {x,y}

### Connection
- id, projectId, fromInsightId (→ Insight), toDataSetId (→ DataSet)

### DataSet  *(2-й уровень)*
- id, projectId, serial, title, chartType (10 типов), columns[], rows[], settings, position {x,y}

### Slide  *(1-й уровень)*
- id, projectId, serial, dataSetIds[], archetype (Chart/Big Number/Comparison/Sentiment/Word List/Quote), narrative, order

### Presentation / Deck
- projectId, themeId (`editorial` | `soft`), slideOrder[], buildAudience, buildTone, narrationMode

### ShareLink
- id, projectId, token, createdAt, revoked (bool) → отдаёт `/p/[id]` read-only

### ProjectVersion
- id, projectId, snapshot, createdAt, label — для истории версий / отката

### ChatMessage
- id, projectId, mode (`data`|`build`), role (`user` | `axon`), content, createdAt — лог живого AI-чата (GigaChat)

## Уведомления

Тосты на ключевые события — короткие, с крестиком, авто-скрытие ~3–4 с:
- **Успех:** «Проект сохранён», «Презентация экспортирована», «Ссылка скопирована».
- **Ошибка:** «Не удалось сохранить / загрузить / разобрать файл» (+ действие «Повторить»).
- **Индикатор автосейва:** «Сохраняю… / Сохранено» в шапке воркспейса (не тост).
- **Email-уведомления** — предпочтения в Настройках сохраняются; реальная рассылка — после v1.
