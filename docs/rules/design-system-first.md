# Design System First — DESIGN.md как контракт

## Принцип
`docs/DESIGN.md` — единственный источник правды для токенов (цвета, шрифты, отступы,
скругления). Направление всегда одно (железное правило №2 в `AGENTS.md`):
**DESIGN.md → `app/components/ui/` → экраны**. Никогда наоборот.

## Правила
1. Любой визуал следует `docs/DESIGN.md`. Источник палитры — `references/palette-reference.png`
   (locked decision, см. `CLAUDE.md`).
2. Нужен новый токен (цвет/шрифт/отступ) → СНАЧАЛА добавить в DESIGN.md, потом использовать.
3. Шрифты/цвета вне контракта не использовать. Исключения-палитры графиков и лендинг —
   перечислены в `ui-components-first.md`.
4. Изменение токена коммитится вместе с зависимыми UI-правками (один коммит — согласованное
   состояние контракта и кода).
5. Темы деки (`PRESENTATION_THEMES`, `--slide-*` переменные) — отдельный слой поверх бренда:
   тема меняет ВСЮ деку через свои переменные, не через точечные правки слайдов.
