# Verification — проверки перед «готово»

## Принцип
Не заявлять «готово» без прохождения проверок. Для доко-коммитов достаточно п.6;
для кода — минимум п.1–3, для UI — все.

## Чек-лист (запуск из `development/apps/app/`)
1. **Типы:** `npx tsc --noEmit` — чисто (железное правило №4 в `CLAUDE.md`).
2. **Lint:** `npm run lint` — 0 замечаний (lint включён в сборку — красный lint валит деплой).
3. **Build (перед деплоем/для крупных правок):** `npm run build` — без ошибок.
4. **Хардкод в UI:** grep из `ui-components-first.md` (страховка-хук делает это же сам).
5. **Мусор:** `grep -rE 'console\.(log|debug)|debugger' app lib --include='*.ts*'` —
   ничего нового не добавлено (существующее — по месту).
6. **Spec sync:** поведение менялось → обновлены `docs/screens/<экран>.md` (+`_global.md`,
   если сквозное) и `docs/test-cases.md` — в том же коммите.
7. **Живая проверка:** локально dev-сервер НЕ поднимать без нужды (Mac, см. state.md);
   реальная проверка фич — на проде после деплоя (smoke, см. будущее правило выкатки — Задание 6).
