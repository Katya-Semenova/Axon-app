# Spec First — спека как источник правды

## Принцип
Прежде чем менять экран или поведение — прочитай спеку. Спека ведёт код, а не наоборот.
Закреплено ADR-011 (spec → test → код) и железными правилами №1/№3 в `AGENTS.md`.

## Правила
1. Перед правкой экрана/поведения читать:
   - `docs/spec.md` — общая логика, модель данных, доступы;
   - `docs/screens/<экран>.md` — состояния, элементы, тексты, валидация;
   - `docs/screens/_global.md` — сквозные правила (auth guard, роли, ошибки сети, успехи,
     loading, двойной submit, формат дат, i18n, empty states, basePath).
2. Меняется поведение → порядок строго: спека → тест-кейс (`docs/test-cases.md`) → код.
   Спека правится в ТОМ ЖЕ коммите, что и код. Коммит без обновления спеки — незавершён.
3. Поведение не меняется (рефактор, стиль) → код остаётся в рамках описанного в спеке.
4. Спеки нет или она поверхностна → сначала допиши спеку, потом код.
5. Спека разошлась с кодом → почини ОДНУ сторону до совпадения; источник правды — спека.
6. Меняется сквозное правило → правь `_global.md` в том же коммите (правило №3 AGENTS.md).
