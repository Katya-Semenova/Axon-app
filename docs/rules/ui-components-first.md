# UI Components First — всё через компоненты, без хардкода

## Принцип
Любой UI сервиса собирается ИЗ компонентов `development/apps/app/app/components/ui/`.
Хардкод классов/стилей в страницах и фичах — запрещён. Меняется визуал → меняется
компонент (или добавляется variant), а не место использования.

## Жёсткие правила
1. Базовые элементы — только компоненты из `app/components/ui/`. Нет нужного — сначала
   создай/дополни компонент там, потом используй на экране.
2. Состояния (hover, focus, disabled, loading) — ВНУТРИ компонента, не на местах использования.
3. Токены — только из `docs/DESIGN.md` (см. `design-system-first.md`). Хексы (`#1A2742`)
   и произвольные пиксели (`w-[16px]`) на страницах — запрещены.
4. Нет нужного варианта — добавь variant в существующий компонент, не плоди
   параллельные компоненты-клоны.
5. **Эталоны и запреты этого репо** (см. «Locked Product Decisions» в `CLAUDE.md`):
   все дропдауны равняются на `ChartTypeDropdown` (JetBrains Mono 11px, checkmark,
   2px radius); квадратный mode-switcher и круглый чат-баббл — намеренно разные, не «унифицировать».

## Легальные исключения
- Палитры/темы графиков в константах: `ChartRenderer.tsx`, `MiniChart.tsx`, `ChartFill.tsx`,
  `PRESENTATION_THEMES` в `lib/types.ts` — там хексы по построению.
- Лендинг (`apps/landing`) — палитра захардкожена inline осознанно (Урок 6; перевод на токены — backlog).

## Самопроверка после большой UI-генерации
grep -rE '#[0-9a-fA-F]{3,8}\b|\[[0-9]+px\]' development/apps/app/app --include='*.tsx' \
  | grep -v -E 'ChartRenderer|MiniChart|ChartFill'
Нашлось — переделать через токены или добавить variant.

## Страховка-хук
`.claude/hooks/post-tool-use-edit.sh` делает этот grep автоматически после каждой правки UI
(см. `docs/automations.md`). Это второй слой; первый — это правило.
