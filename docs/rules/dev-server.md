# Dev-сервер — один на машину

## Правило (для AI — железное)
1. **Максимум ОДИН dev-сервер на весь Mac.** Перед запуском — спросить пользователя,
   не запущен ли сервер в другом параллельном чате. Уже запущен → НЕ поднимать второй.
2. Запускать только через `run_in_background`; по окончании работы — **обязательно погасить**
   (TaskStop). Осиротевший сервер = следующий чат уронит машину.
3. Для автотестов/проверок предпочитать **прод-сборку**: `npm run build` + `npm start`
   (легче dev-режима: нет слежения за файлами и пересборки на лету). Тоже гасить после прогона.
4. Vitest-тесты (без браузера) сервера не требуют — гонять свободно.
5. Проверку живых фич по возможности делать на проде после деплоя, а не локально.

## Почему правило существует (факты)
- 2026-06-22 Mac завис намертво («fork failed»): несколько чатов параллельно плодили
  dev-серверы, осиротевшие node-процессы накопились и исчерпали ресурсы.
- Диагностика 2026-07-04: машина сильная (Mac mini M4 Pro, 24 ГБ, 12 ядер) — проблема
  не в железе, а в накоплении процессов. Один аккуратный сервер она держит спокойно.

## Команды
- Запуск сервиса: `cd development && npm run dev -w apps/app -- -p 3001`
- Запуск лендинга: `cd development && npm run dev -w axon-landing -- -p 3002`
- Убить все dev-серверы Next (безопасно для VS Code/чатов): `pkill -f "next dev"`
- Что сейчас запущено: `ps aux | grep "[n]ext"`
