# Commits — авто-коммит после каждого логического шага

## Принцип
Каждая завершённая фича / фикс / оформленный документ → **коммит СРАЗУ, автоматически,
не дожидаясь команды**. Не накапливать изменения: на этом репо параллельно работают
несколько чатов, незакоммиченные правки молча затираются (проверено 2026-06-24).

## Правила
1. Завершил шаг → `git add <конкретные файлы шага>` + `git commit` сразу.
   Перед началом работы — `git status` (увидеть чужие незакоммиченные правки и НЕ включать их).
2. Атомарно: одна фича/один фикс = один коммит. Спека/доки/тесты шага — в том же коммите.
3. **НЕ `git add -A` / `git add .`** — только файлы своего шага поимённо
   (не утащить `.env`, чужие правки, мусор). Папку `lessons/` не коммитить никогда (.gitignore).
4. **Формат сообщения — как сложился в этом репо:** `тип(зона): описание по-русски`,
   тип ∈ feat / fix / refactor / docs / chore / i18n.
   Примеры из истории: `fix(slides): пустое состояние — «Холст» вместо…`,
   `docs(backlog): показ 2026-07-04 — …`, `chore(lint): закрыть долг…`.
5. Перед коммитом — чек-лист `verification.md` (для кода минимум tsc + lint).
6. **Push — ЗА ПОЛЬЗОВАТЕЛЕМ.** Автодеплоя на push нет (деплой — руками `./deploy.sh`),
   но пуш пользователь делает сам: AI пуш не выполняет без явной просьбы, а после серии
   коммитов — напоминает/предлагает запушить.
