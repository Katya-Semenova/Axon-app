# Правила безопасности проекта AXON (для AI и /security-check)

> На этот файл опираются проверки безопасности. Дополняется при каждой находке.
> Вектора по разделам — `docs/security-checklist.md`; аудиты — `docs/audits/`.

## Модель угроз (что считать ДЫРОЙ — чинить немедленно)
1. **Доступ к чужим данным:** любой путь, где пользователь A видит/меняет/удаляет
   доску, файл, аватар или чат пользователя B. Владелец — ТОЛЬКО из серверной сессии
   (`auth.api.getSession`), проверка `ownerId === userId`; чужое → «как 404», не «Forbidden».
2. **Обход входа:** серверный экшен или API-роут без гейта сессии первой строкой.
3. **Утечка секретов:** ключи (OpenRouter, S3, Resend, BETTER_AUTH_SECRET) в git,
   в клиентском бандле, в логах или в ответах API. Ключи живут только в `.env*` (gitignored)
   и на сервере. `NEXT_PUBLIC_*` — только заведомо публичное (YM_ID).
4. **Раскрытие существования:** скрытые поверхности (/admin, /storybook) чужим отвечают 404,
   не редиректом и не 403. Вход отвечает обезличенно («Invalid email or password»).

## Особенности продукта
- **Данные пользователя = его файлы.** Разбор CSV/Excel происходит в браузере; ИИ-провайдеру
  уходит только схема колонок + выборка строк. Полную таблицу наружу не отправлять.
- **ИИ-endpoints** (`/api/ai/*`): только вошедшим (401 гостю), лимиты обязательны
  (демо-режим: 5/час на IP). Prompt-injection: пользовательский текст в промптах —
  только как данные, числа считает код (гибрид), ИИ не получает инструментов записи.
- **Заголовки файлов** из выгрузок нейтрализуются от формульных инъекций (`=`,`+`,`@` → `'`)
  — покрыто тестом.
- **Роль админа** — по `ADMIN_EMAIL` (env), не от клиента; server-only модуль `lib/admin.ts`.

## История багов (не повторять)
- **Path-traversal в `/api/files`** (Урок 6, починен): ключ файла из URL нельзя
  подставлять в путь/ключ хранилища без проверки принадлежности пользователю.
- **ИИ-env не доехал в Docker** (Урок 5): секреты compose должны быть и в `environment`,
  а `NEXT_PUBLIC_*` — ещё и в `build.args` (впекается на сборке).
- Rate-limit Better Auth хранится в памяти процесса — сбрасывается при передеплое (принято).
