# /ux-testing — живой прогон UI в браузере

Ты проходишь сценарии продукта в НАСТОЯЩЕМ браузере через инструменты Playwright MCP
(`browser_navigate`, `browser_snapshot`, `browser_click`, `browser_fill_form`,
`browser_take_screenshot`, `browser_resize`) и пишешь отчёт. Это НЕ автотесты:
смысл — увидеть глазами то, что автоматика не ловит (визуальные поломки, адаптив, тексты).

## Параметры (спроси, если не сказаны)
1. **Где проверяем:** прод `https://axon-app.ru` (+ сервис `/ai-studio`) или локальная
   прод-сборка `http://localhost:3101` (поднять: `bash tests/e2e/server.sh` из `apps/app` —
   НЕ dev-сервер, см. `docs/rules/dev-server.md`). ⚠️ На проде может стоять Basic Auth (axon/…).
2. **Что проверяем:** по умолчанию — сценарии из `docs/test-cases.md` (1, 2, 4, 5, 6);
   либо конкретный экран/фича, которую только что меняли.
3. **Адаптив:** нужен ли прогон ширин 320 / 768 / 1024 / 1440 (по умолчанию — только 1440;
   мобильным сервис отдаёт заглушку «лучше с десктопа» — это ожидаемо, не баг).

## Шаги
1. Прочитай `docs/test-cases.md` (Дано/Когда/Тогда) и паспорт проверяемого экрана из `docs/screens/`.
2. Для каждого сценария: пройди шаги в браузере; после каждого значимого шага —
   `browser_snapshot`; при расхождении или подозрении — `browser_take_screenshot`
   (складывай в scratchpad, не в репозиторий).
3. Сверяй с «Тогда» сценария И со сквозными правилами `docs/screens/_global.md`
   (loading, ошибки сети, empty states, i18n, basePath).
4. ⚠️ На ПРОДЕ: не удаляй чужие данные, не сбрасывай базу (`docs/rules/production-safety.md`);
   для регистрации используй адреса вида `ux-test-<дата>@test.local`; свои тестовые
   проекты/аккаунты после прогона предложи удалить руками.
5. Если сценарий требует данных — файл-образец бери из `test-data/`.

## Отчёт (в конце, обязательно)
Таблица: сценарий → ✅ ок / 🟡 расхождение (что именно + скриншот) / 🔴 сломано.
🔴 — предложи диагноз по правилу CLAUDE.md (цитата кода → причина одной фразой → фикс),
но НЕ чини без подтверждения. 🟡 — предложи записать в `docs/backlog.md` (в конец, коммит сразу).
Если прогон был после деплоя и всё ✅ — так и скажи: «smoke руками пройден».

## Edge cases
- Basic Auth на проде → попроси у пользователя логин/пароль, не подбирай.
- ИИ-фичи на проде тратят реальный ключ — прогоняй ИИ-сценарии только по явной просьбе.
- Rate limit входа (10/60с) — не долби форму логина в цикле.
- Playwright MCP недоступен → предложи fallback: `npm run test:e2e` (автотесты) + ручной чек-лист.
