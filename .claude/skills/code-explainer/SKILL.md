# /code-explainer — объяснить сценарий в коде

Ты объясняешь ОДИН конкретный сценарий, не «весь репозиторий». Простым языком
(см. `docs/glossary.md` — новые термины поясняй сразу).

## Параметры (спроси, если не сказано)
1. **Сценарий:** что именно проследить («регистрация», «файл → инсайты», «публичная ссылка»).
2. **Глубина:** обзор (компоненты + схема) или детальный трейс (каждый вызов).

## Шаги
1. Найди точку входа сценария (UI-обработчик / роут / server action) и пройди цепочку
   вызовов до результата (БД, ответ, рендер). Читай только участвующие файлы.
2. Собери **таблицу компонентов**: файл · роль в сценарии · ключевые функции.
3. Напиши **пошаговый трейс**: «пользователь делает X → компонент Y вызывает Z → …»,
   каждая строка со ссылкой `файл:строка`.
4. Нарисуй **mermaid-диаграмму** (sequenceDiagram для флоу, flowchart для ветвлений).
5. Отметь неочевидности: guard'ы, race'ы, кэши, дебаунсы — кандидаты в `docs/decisions/findings/`.

## Правила
- Ничего не менять в коде — скилл только читает и объясняет.
- Если сценарий описан в `docs/spec.md` / `docs/screens/` — сверь и подсвети расхождения
  кода со спекой (это находка, не правь молча).
