# Сохранение прогресса в память проекта

Цель: когда завершена цельная работа (фича, законченный набор правок, этап) — зафиксировать, что сделано, какие решения приняты и где остановились, чтобы следующая сессия не начинала с нуля.

## Когда применять
- Завершён цельный этап: урок, фича, законченный набор правок.
- Перед длинным перерывом (день+).
- **НЕ применять для мелких правок** (опечатка, цвет одной кнопки) — для них хватает git-коммита.

## Параметры
Спроси у пользователя одной строкой, если не задано:
- **Slug сессии** — короткое имя файла, напр. `lesson-06-package`, `auth-mvp`.
- **Краткое описание** — 1–2 предложения, что делали (если ты участвовал — помнишь сам).

Дата сессии = текущая (`date +%Y-%m-%d`).

## Пути в ЭТОМ репозитории (axon-app)
- Журналы сессий: **`docs/decisions/sessions/<YYYY-MM-DD>-<slug>.md`**
- Текущий статус: **`docs/memory/state.md`**
- Оглавление (ADR + журнал сессий): **`docs/decisions/INDEX.md`**

## Шаг 1 — Собери саммари сессии
Если участвовал — собери сам:
- **Что сделано:** 3–7 главных результатов.
- **Изменённые файлы:** `git diff --stat HEAD~N..HEAD` (N = число коммитов сессии) или `git status`.
- **Принятые решения:** архитектурные/дизайн-выборы — кратко почему.
- **Находки:** неочевидное поведение, лимиты, грабли.
- **Открытые вопросы / следующие шаги.**

Если не участвовал (свежий старт) — попроси пользователя описать в одном сообщении.

## Шаг 2 — Создай session-файл
Путь: `docs/decisions/sessions/<YYYY-MM-DD>-<slug>.md`. Если такой уже есть — добавь номер (`-2`). Шаблон (пустые разделы удаляй):

```markdown
# <YYYY-MM-DD> — <Описание сессии>

**Контекст:** <задача / этап>

## Что сделано
- ...

## Изменённые файлы
<вывод git diff --stat>

## Принятые решения
- <решение> — кратко почему

## Находки
- <нюанс / грабли>

## Открытые вопросы / следующие шаги
- ...

## Связанное
- Предыдущая сессия: <YYYY-MM-DD>-<slug>.md
```

## Шаг 3 — Обнови `docs/memory/state.md`
- **Текущая фаза** — на следующий шаг (напр. «Урок 6 закрыт → Урок 7»).
- **Что сделано** — добавь 1–2 главных пункта.
- **Бэклог** — убери выполненное, добавь следующее.
- Держи `state.md` коротким: разросшееся выноси/удаляй — история в `sessions/`.

## Шаг 4 — Обнови `docs/decisions/INDEX.md`
Добавь строку в журнал сессий в начало (реверс-хронология):
```
| YYYY-MM-DD | <задача / этап> | [<filename>](sessions/<filename>) |
```
Если раздела «Журнал сессий» нет — создай таблицу.

## Шаг 5 — Покажи результат
Выведи пользователю: путь к session-файлу, обновлённый статус из `state.md`, список открытых вопросов на следующую сессию.

## После
Закоммить изменения памяти отдельным коммитом, напр. `docs(session): журнал <slug> + обновлён state`. Спека-правила проекта (AGENTS.md): spec.md/DESIGN.md держим актуальными — если в сессии менялось поведение/визуал, проверь, что они обновлены.
