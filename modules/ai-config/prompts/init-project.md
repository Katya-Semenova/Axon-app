# init-project — старт нового проекта одной фразой

> Универсальный модуль библиотеки. Собран в финале курса (2026-07-04).

Пользователь говорит одной фразой, что делает («новый проект: приложение для учёта книг»,
«пишу лендинг для студии», «делаю книгу рецептов»). Дальше ведёшь ты — не допрашивая
о том, чего в проекте явно нет.

## Шаги

1. **Пойми направление по фразе.** Какие направления библиотеки нужны:
   - есть продукт/сервис → `modules/product` (PRD-интервью) обязательно;
   - есть интерфейс → `modules/design` (дизайн-система, UI-кит);
   - есть код/бэкенд → `modules/development` (БД, auth, деплой, тесты);
   - нужен публичный сайт → `modules/seo-geo`;
   - память и правила (`modules/ai-config`) — нужны ВСЕГДА.
   «Пишу книгу» → продукт/контент, БЕЗ дизайн-системы и бэкенда. Не спрашивай про
   деплой у того, кто пишет текст.

2. **Подними каркас проекта** (спроси только имя папки, если не очевидно):
   - папка проекта; `git init` + первый коммит; `.gitignore` (node_modules, .env*, тяжёлые артефакты);
   - `AGENTS.md` — железные правила + таблица «читать по триггеру» (образец — `modules/ai-config/prompts/rules-setup.md`);
   - память: `docs/memory/state.md` (заглушка «где мы»), `docs/decisions/INDEX.md`,
     `docs/decisions/sessions/` — по `modules/ai-config/prompts/memory-setup.md`;
   - `docs/spec.md` — пустой каркас (заполнит продуктовый этап).

3. **Предложи маршрут** — 3–5 первых шагов ИЗ БИБЛИОТЕКИ, по одному промту на шаг,
   с путями (например: `modules/product/prompts/prd-interview.md` → `modules/design/prompts/design-tokens.md` → …).
   Спроси, с какого начать. Не запускай всё подряд сам.

4. **Правило дальше:** в конце каждого этапа — `/save-session`; переносимые наработки —
   в библиотеку через `/extend-library`.

## Edge cases
- Проект уже существует (есть git/файлы) → не пересоздавай; предложи только недостающее (память, AGENTS.md).
- Пользователь не назвал имя → предложи 2–3 варианта slug-имени папки.
- Непонятно направление → задай ОДИН уточняющий вопрос, не анкету.
