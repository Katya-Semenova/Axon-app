# Выбор ORM (Prisma vs Drizzle) — дополнение ADR «слой данных» (опционально)

> Универсальный модуль библиотеки. Происхождение: курс vibecoding, урок 04 (обезличено 2026-07-04).

> **Опционально.** По умолчанию Prisma прикручивается автоматически на шаге со схемой (`db-schema-migrations-seed.md`) — отдельно ORM выбирать не нужно. Этот промт — для тех, кто хочет осознанно сравнить Prisma и Drizzle и, возможно, взять Drizzle. Если такого желания нет, пропустите: дефолт Prisma уже записан в ADR при выборе базы (`db-choice.md`).

> **Цель:** при желании — осознанный выбор Prisma vs Drizzle, дописанный в раздел «ORM» того же `ADR-XXX-data-layer.md`, с обоснованием отвергнутой альтернативы.

## Промт

```
Объясни мне коротко (5-7 минут чтения):

- Что такое реляционная БД (таблицы, ключи, связи) на пальцах
- Зачем ORM — чтобы не писать SQL руками, иметь типы из схемы автоматически,
  миграции из коробки
- Prisma vs Drizzle — плюсы и минусы каждого

Сравнительная таблица:

| | Prisma | Drizzle |
|---|---|---|
| Зрелость | Стабильная, много пользователей | Молодая, активно растёт |
| Типы | Auto-generated client из schema.prisma | Из TS-схемы |
| SQL | Скрыт за абстракцией | Очень близко к SQL |
| Миграции | prisma migrate (декларативные) | drizzle-kit (декларативные) |
| Перформанс | Чуть медленнее (генерация SQL) | Близко к raw SQL |
| AI-помощь | Очень много примеров в обучающих выборках | Меньше, но растёт |
| Edge runtime | Сложнее (Prisma Client тяжёлый) | Из коробки |

Затем порекомендуй один с обоснованием. Учти:
- Тип продукта по docs/PRD.md
- Что AI генерирует большую часть кода (Prisma — больше примеров в обучении)
- Мой уровень опыта в SQL (если SQL не знаю — Prisma скрывает SQL, для меня плюс)
- Что базу я уже выбрал в прошлом промте (db-choice.md: Supabase или свой
  Postgres). ORM работает с обоими одинаково — внутри это тот же PostgreSQL,
  меняется только DATABASE_URL.

Допиши решение по ORM в УЖЕ СОЗДАННЫЙ
docs/memory/decisions/ADR-XXX-data-layer.md (его начал промт db-choice.md
— там уже есть раздел «База данных», Status и Date). Не создавай новый файл, а
дополни существующий.

В раздел Decision добавь подраздел ORM:

### ORM
<Prisma|Drizzle> — потому что <причина под мой проект>.

В Consequences допиши последствия выбора ORM (положительные и отрицательные).
В Alternatives Considered добавь отвергнутые ORM-варианты:

### <Prisma|Drizzle> (тот, что НЕ выбрали)
- Плюсы: ...
- Минусы: ...
- Почему не выбрали: ...

### Голый SQL через pg-клиент
**Отвергли:** нужно знать SQL глубоко, нет миграций из коробки, нет типов
автоматом — слишком высокий вход для не-бэкендера.

### TypeORM / Sequelize
**Отвергли:** устарели по сравнению с Prisma/Drizzle, у AI меньше "опыта" в
обучении, развитие медленнее.

### Без ORM (просто Postgres + написание raw SQL в каждой функции)
**Отвергли:** теряем типы, миграции, защиту от SQL injection через placeholders.
Слишком хрупко для прода.

просто оставь как есть.)
```

## Edge cases

- Если у пользователя уже есть опыт SQL — Drizzle может быть приятнее (ближе к SQL)
- Для большинства проектов по умолчанию **Prisma — оптимальный выбор**: больше примеров в обучении AI, более «толстая» абстракция, скрывающая SQL
